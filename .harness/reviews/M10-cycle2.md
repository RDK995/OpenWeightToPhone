### The finding-2 override — reasoning holds, shape is correct

Reason (a) is decisive on its own: `void deps.cachePut(...).catch(() => {})` attaches the
handler only *after* the call returns, so a **synchronous** throw propagates into the outer
`catch` and the defect survives in its worst form. The implemented inner `try`/`catch` at
`web/src/sw.ts:53-58` sits inside `if (networkResponse.ok)` and catches both rejection and
synchronous throw, and the new third test (`throwingCachePut`) covers the synchronous case
that the suggested correction would have missed. Reason (b) is also sound in kind: the
pre-existing discriminating test at `test/web/sw.test.ts:138-171` asserts
`expect(cachedBody).toBe("NEW BUILD")` *after* `handleShellRequest` resolves, which a
fire-and-forget write would make a race. The fix was confirmed to behave correctly against a
real server in both the empty-cache and warm-cache cases.

## Findings

**Severity:** OPTIONAL

**Problem:** Finding 3's fix closed three of four relative asset references.
`navigator.serviceWorker.register("./sw.js")` in `web/src/main.ts` is still relative, so on
the bare `/app` (no trailing slash) entry point it resolves to the origin root and the
service worker silently fails to register.

**Evidence:** `web/src/main.ts:54` — `navigator.serviceWorker.register("./sw.js").catch(() => {});`
(present verbatim in the served bundle at `/app/main.js:1345`). Live: `GET /app` → 200
`text/html` with no redirect, and `GET /sw.js` → **401**. The registration rejection is
swallowed by the `.catch(() => {})`. The new guard test at `test/web/manifest.test.ts:125-129`
asserts only on `web/public/index.html`, so it does not cover this reference.

**Why it matters:** Strictly milder than the original finding — the shell itself now loads
correctly from bare `/app` because its three references are absolute, so the user gets a
working app, just with no service worker and therefore none of the network-first caching this
milestone built. It is the residue of an OPTIONAL finding rather than a new defect, and the
sanctioned path (`pairingUrl()` in `src/host/config.ts:80-85`, which emits the trailing slash)
is unaffected. But the trap the fix set out to close is only 3/4 closed.

**Suggested correction:** Change the registration to `navigator.serviceWorker.register("/app/sw.js")`
— the resulting scope is identical (`/app/`) — and extend the new guard so it also asserts no
`"./"` argument to `register(` in `web/src/main.ts`, or fold both into a single check over the
shell's emitted references.

**Suggested correction:** Re-indent lines 176-198 to the `for`-body level. No behavioural

## Verdict

**PASS**

All four acceptance criteria pass on evidence the reviewer gathered itself, including a live
`kill -9` respawn of the production launch agent and an independent rebuild-freshness harness
that also exercises the corrected cache-write failure path. The correction patch touches
exactly the eight disclosed files and no others, and the working tree is byte-identical to the
post-correction snapshot.

The widening was justified and the claim it was widened to test **holds**:
`test/web/manifest.test.ts` lost nothing, loosened nothing, and gained a strictly new
assertion, and all four of its index.html assertions were proven to fail against the
pre-correction HTML. The known "guard test that asserts nothing" failure mode is not present
here — the fix cycle's discrimination proofs were reproduced by execution rather than
credited: 21/3 on `sw.test.ts` and a failing drift check on a single flipped byte, both
against reverted code in a scratch tree, with the repository's icons demonstrably untouched
throughout.

The finding-2 override of the report's suggested correction was correct and the implemented
shape genuinely fixes the defect in both the empty-cache and warm-cache cases, including the
synchronous-throw case the suggested correction would have missed.

`bun run proof:m10` was not run. The service is left healthy at **pid 74807**,
`state = running`, `runs = 5`, `/app/` 200 on loopback and over the tailnet.

Neither OPTIONAL finding blocks the verdict; both are cheap and can be folded into M12 or
taken now at the fixer's discretion.
