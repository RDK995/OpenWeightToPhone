TASK

Goal:
Add a `setProfileId(conversationId, profileId)` method to the Conversation Store (C8) so a
conversation's profile can be changed after it has been created.

Tier: Cheap. Routing reason: none — this is clearly specified, bounded to one file plus its
test, low risk, and settled by `bun test`. It mirrors the existing `setSessionId` method
exactly.

Relevant Requirements:
- FR5 (Profiles): "Profile is selectable per conversation and changeable."
- Milestone M3, criterion: "A conversation's profile can be changed, and the next generation
  runs under the new profile."
- Architecture C8 — Conversation Store, `web/src/conversation-store.ts`.

Acceptance Criteria:
- `ConversationStore` gains `setProfileId(conversationId: string, profileId: string): Conversation`,
  declared on the exported `ConversationStore` interface and implemented.
- It follows the existing `setSessionId` implementation pattern precisely: resolve the
  conversation via the existing `requireConversation` helper, mutate, bump `updatedAt`,
  `persist()`, and return a deep copy (the same non-aliasing guarantee the other methods give).
- Calling it for an id that does not exist throws, the same way `setSessionId` does for a
  missing conversation. Match the existing behaviour rather than inventing a new one.
- The change survives a reload: a second store constructed over the same storage port reads
  back the new `profileId`.
- The returned object does not alias internal state — mutating `returned.profileId` afterwards
  must not change what is persisted.
- Tests are added to `test/web/conversation-store.test.ts` covering each of the above. Write
  the test first, watch it fail, then implement (Red -> Green -> Refactor).

Relevant Files:
- `web/src/conversation-store.ts` — read `setSessionId`, `requireConversation`,
  `deepCopyConversation` and `persist` before writing anything; copy their shape.
- `test/web/conversation-store.test.ts` — read the existing `setSessionId` tests and follow
  their structure and naming.

Files Allowed To Change:
