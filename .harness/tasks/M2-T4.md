Goal:
Implement C8 — Conversation Store. Own the locally persisted conversations, their
transcripts, and the progress of any in-flight generation. Persist through the Storage Port.

Relevant Requirements:
- Architecture C8 — Conversation Store: "Own the locally persisted conversations, their
  transcripts, and the progress of any in-flight generation." Location:
  `web/src/conversation-store.ts`. Depends on: C11.
- Architecture Data, quoted verbatim:
  - "`Conversation` — `{ id, title, sessionId, profileId, turns, pending, createdAt, updatedAt }`.
    Owned by C8, persisted through C11 under a versioned key in `localStorage`."
  - "`Turn` — `{ role, content, cancelled, createdAt }`. A local mirror of the service's
    turns, which is what makes FR8's replay possible after the server's in-memory session is
    lost."
  - "`PendingGeneration` — `{ generationId, lastSeq, status }`. Persisted rather than held in
    memory, because iOS may terminate a backgrounded page outright; without this on disk a
    resume is impossible."
- Architecture interface "C9 → C8": `loadConversations()`, `saveConversation(conversation)`,
  `recordProgress(conversationId, { generationId, lastSeq })`.

Acceptance Criteria:
- `web/src/conversation-store.ts` exports types:
  - `Turn` = `{ role: "user" | "assistant"; content: string; cancelled: boolean; createdAt: string }`
  - `PendingGeneration` = `{ generationId: string; lastSeq: number; status: string }`
  - `Conversation` = `{ id: string; title: string; sessionId: string | null; profileId: string;
    turns: Turn[]; pending: PendingGeneration | null; createdAt: string; updatedAt: string }`
- It exports `createConversationStore(storage: StoragePort): ConversationStore`, importing
  `StoragePort` as a type from `./storage-port`.
- `ConversationStore` has exactly these methods:
  - `loadConversations(): Conversation[]`
  - `getConversation(id: string): Conversation | null`
  - `createConversation(input: { profileId: string; title?: string }): Conversation` —
    generates an id via `crypto.randomUUID()`, sets `sessionId: null`, `turns: []`,
    `pending: null`, and `createdAt`/`updatedAt` to the same ISO-8601 UTC string. Persists it.
  - `saveConversation(conversation: Conversation): void` — upserts by `id` and sets
    `updatedAt` to now. Persists.
  - `appendTurn(conversationId: string, turn: Turn): Conversation` — appends to `turns`,
    bumps `updatedAt`, persists, returns the updated conversation.
  - `setSessionId(conversationId: string, sessionId: string): Conversation` — persists.
  - `recordProgress(conversationId: string, pending: PendingGeneration | null): Conversation`
    — sets `pending` (passing `null` clears it), persists.
- All conversations are stored under a single **versioned** key, exported as a named
  constant, of the form `phone-to-local-model:v1:conversations`.
- Persistence is real: a second store constructed over the *same* `StoragePort` sees
  everything the first one wrote. Prove this in a test — it is the reload case.
- `loadConversations` returns `[]` when nothing is stored, and returns `[]` rather than
  throwing when the stored value is corrupt (not JSON, or not an array). Corrupt local
  storage must not brick the app.
- `loadConversations` returns conversations ordered by `updatedAt` descending (most recently
  touched first) — this is the list-view order M8 will need.
- `getConversation` returns `null` for an unknown id.
- The mutating methods throw a clear `Error` naming the unknown id when called with a
  conversation id that does not exist.
- Mutations do not alias caller state: mutating a `Conversation` object returned by the
  store must not silently change what is persisted. Return copies. Prove this in a test.
