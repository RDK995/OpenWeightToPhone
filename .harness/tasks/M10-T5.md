Acceptance Criteria:

Create `src/host/m10-proof.ts`, following the conventions of the existing proof scripts —
read `src/host/m8-proof.ts` first for the house style (a `main()`, phase banners printed as
`=== PHASE n: NAME ===`, per-check `PASS`/`FAIL` lines, an `allPassed` flag, a final

**PHASE 1 — Manifest and icons resolve at the served origin.**
Derived criterion: "The web app manifest parses, declares `display: standalone` and a
`start_url` under `/app/`, and every icon it names resolves 200 with an image content type
at `https://ryans-mac-studio.tailc3648a.ts.net/app/`."
- Take the origin from `resolveBaseUrl()` and the mount from `APP_MOUNT_PATH`, both in
  `./config.ts` — do NOT hardcode the hostname.
- `GET <origin>/app/` → assert 200 and a `text/html` content type, and that the body
  contains `rel="manifest"` and `apple-mobile-web-app-capable`.
- `GET <origin>/app/app.webmanifest` → assert 200, assert the `Content-Type` is
  `application/manifest+json`, and `JSON.parse` the body (report the parse failure loudly
  if it fails — an unparseable manifest is exactly what makes an install fail silently).
- Assert `display === "standalone"` and that `start_url` starts with `/app/`.
- For EVERY entry in `icons`: resolve its `src` against the origin, `GET` it, and assert
  status 200, a `Content-Type` starting with `image/`, a non-empty body, and that the first
  eight bytes are the PNG signature `89 50 4E 47 0D 0A 1A 0A`. Print one line per icon with
  its URL, status, content type and byte length. A manifest naming an icon that 404s is the
  failure this check exists to catch, so every icon must be fetched — do not stop at the
  first.

**PHASE 2 — A rebuilt bundle is not pinned behind a stale cache.**
Derived criterion: "The service worker registers with a versioned cache name and a
network-first strategy for the shell: after the bundle is rebuilt, a fetch through the
worker's strategy returns the new build, not the cached one."
Prove this against a REAL build and a REAL HTTP server, not only fakes:
- Make a temp directory `<tmp>`; copy the repository's `web/` directory into `<tmp>/web`
  (source and public only are needed, but copying `web/` wholesale is fine — delete any
  copied `web/dist` first so the build starts clean).
- `import { build } from "../../scripts/build.ts"` and run `build({ root: tmp })`. Read
  `<tmp>/web/dist/main.js` and hash it — call this BUILD 1.
- Start the real asset server over the temp bundle:
  `createPwaServer({ port: 0, bundleRoot: <tmp>/web/dist })` from `./pwa-server.ts`, and
  take the actual bound port from the returned server's `url`/`port` (port 0 means the OS
  picks a free one, so nothing can collide with the production server on 7788).
- Build a Map-backed cache implementing the `deps` shape that
  `handleShellRequest` from `../../web/src/sw.ts` expects (`fetch`, `cacheMatch`,
  `cachePut`), where `fetch` is the global `fetch` against the temp server.
- Warm the cache: call `handleShellRequest` for `http://127.0.0.1:<port>/app/main.js` and
  assert the returned body equals BUILD 1 and that the cache now holds BUILD 1.
- Now REBUILD with a changed source: append a line such as
  `export const __M10_PROOF_MARKER = "rebuilt";` to `<tmp>/web/src/main.ts`, run
  `build({ root: tmp })` again, read `<tmp>/web/dist/main.js` and hash it — call this
  BUILD 2. Assert BUILD 2 !== BUILD 1 (if the hashes match, the rebuild did not happen and
  the whole phase proves nothing — fail loudly rather than passing vacuously).
- Call `handleShellRequest` again for the same URL. Assert the returned body equals
  BUILD 2, NOT BUILD 1. Print both hashes and which one was returned.
- Add the DISCRIMINATING control: assert that the cache entry seen BEFORE this second call
  was BUILD 1 — i.e. a cache-first strategy would have returned the stale build. Without
  that control the assertion above could pass on an empty cache and prove nothing.
- Assert the cache was refreshed: after the second call, the cached entry is BUILD 2.
- Assert `CACHE_NAME` contains `CACHE_VERSION` (the versioned-cache half of the criterion),
  importing both from `../../web/src/sw.ts`.
- Stop the temp server and remove the temp directory in a `finally`, whatever happens.

**PHASE 3 — The launch agent starts the asset server and restarts it after it dies.**
Derived criterion: "The launch agent starts the asset server at load and restarts it after
it exits — proven by killing the process and observing `/app/` serve again without manual
intervention."
This phase installs the PRODUCTION agent and leaves it installed and running — that is the
milestone's deliverable, not a side effect to clean up.
- Import `LAUNCH_AGENT_LABEL`, `launchAgentPlistPath`, `renderPlist` and
  `installLaunchAgent` from `./launch-agent.ts`. Use the real collaborators, exactly the
  ones `launch-agent.ts`'s own `import.meta.main` block uses — do not duplicate that logic,
  export and reuse it if that is cleaner, but if you do, the only change permitted to
  `src/host/launch-agent.ts` is exporting something already written; do not alter its
  behaviour.
- Port comes from `resolvePwaPort()`, bundle root from `resolveBundleRoot()`, both from
  `./config.ts`. The bun binary path: prefer `process.execPath`, falling back to
  `$HOME/.bun/bin/bun`. Log directory `$HOME/Library/Logs/phone-pwa/` — create it.
- **Before installing**, free the port: run `lsof -ti tcp:<port>` and `kill` any PID it
  returns (this is the manually-started asset server from earlier milestones — PID 9227 at
  the time of writing). Wait until the port is free. If you skip this, `bootstrap` will
  appear to succeed while the agent's process dies on `EADDRINUSE` in a restart loop, and
  the phase would pass against the OLD server while proving nothing.
- Run `installLaunchAgent(...)`. Then poll `http://127.0.0.1:<port>/app/` every 500ms for up
  to 30s until it returns 200. Assert it does. Record the serving PID (via
  `lsof -ti tcp:<port>`) as PID_1.
- `kill -9 PID_1`.
- Poll again, every 500ms for up to 45s, until `http://127.0.0.1:<port>/app/` returns 200
  AND `lsof -ti tcp:<port>` reports a PID different from PID_1. Assert both. Print PID_1 and
  PID_2. Identical PIDs mean you never actually killed it — that must FAIL, not pass.
- Finally, assert the TAILNET origin `<origin>/app/` still returns 200 after the restart, so
  the proof covers the path the phone actually uses, not just loopback.
- Leave the agent loaded. Print the plist path and the label so the human can see what was
  installed, and print the exact `launchctl bootout` command that would remove it.
