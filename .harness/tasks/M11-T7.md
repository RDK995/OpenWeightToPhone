The script must prove, as separate labelled sections:

1. **AC1 — QR round-trip through an independent decoder.**
   - Read the real token via `readToken()` and build the real pairing URL with
     `pairingUrlWithToken(token)`. **Never print the pairing URL or the token.**
   - `encodeQr(pairingUrl, { ecc: "M" })` -> `matrixToPng` -> write to a temp file ->
     `swift scripts/qr-decode.swift <png>`.
   - Assert the decoder exits 0 and its payload is **byte-identical** to the pairing URL.
   - Print evidence that does not leak: the decoder's exit status, the payload's **length** and
     its **sha256**, alongside the input pairing URL's length and sha256, and assert they match.
     Print the QR's version and size. Do NOT print the payload itself.
   - Also round-trip a **non-secret** control string (e.g.
     `https://ryans-mac-studio.tailc3648a.ts.net/app/#t=` + 43 `A`s) and print that payload in
     full, so a reviewer can see a real decoded value without a credential being disclosed.

2. **AC2, agent-provable half — the credential store, then a live authenticated call.**
   - Import `adoptCredentialFromFragment` and the credential store from
     `web/src/credential-store.ts` (see how the existing tests construct it — inject a fake
     storage and a fake location; there is no browser here).
   - Feed it a location whose hash is the **real pairing URL's fragment**. Assert it: returns
     the credential, **persisted the token into the injected storage**, and **cleared the
     fragment** (assert the fake location's hash is now empty, and that the token does not
     appear anywhere in the location object afterwards).
   - Then read the token **back out of the injected storage only** and use it for a live call:
     `GET <baseUrl>/v1/profiles` with `Authorization: Bearer <stored token>`.
     **Assert the status is 200.** Print the status and the number of profiles returned.
   - Then make the **same request with no Authorization header** and **assert the status is
     401**, proving the 200 was earned by the credential rather than by the endpoint being open.
   - **Use `/v1/profiles`. `/v1/status` is NOT a route on this harness — it 404s.**
   - Print, clearly, that the optical camera step of AC2 is human-attested and NOT proven here.

3. **Derived criterion — the permission refusal.**
   - **Prove this against FIXTURE files in a temp directory. Never modify the real token file.**
   - Before and after this whole section, `stat` the real token file
     (`~/.openweight-harness/token`, or `resolveTokenPath()`), and assert its mode is still
     `0600`; print the mode, size and mtime both times and assert the mtime is unchanged.
   - Create fixture token files with a dummy (non-real) token and assert `readToken` behaviour
     via `OPENWEIGHT_HARNESS_TOKEN_FILE`:
     - mode `0600` -> returns the dummy token (proves the fixture path works at all, and that
       `OPENWEIGHT_HARNESS_TOKEN_FILE` is honoured);
     - mode `0644` (world-readable) -> **throws, and the dummy value is not returned**;
     - mode `0640` (group-readable) -> throws;
     - mode `0604` (other-readable) -> throws.
   - For each refusal, print the error message and assert the dummy token value does not appear
     in it.
   - Also assert `OPENWEIGHT_HARNESS_TOKEN_FILE` is honoured by showing `resolveTokenPath` with
     the variable set returns the fixture path, and unset returns the `~/.openweight-harness/token`
     default.

4. **Derived criterion — the CLI does not print the token.**
   - Run the pairing CLI's default output path **against a fixture token file** with a
     distinctive dummy 43-character token (via `OPENWEIGHT_HARNESS_TOKEN_FILE`), capturing
     stdout and stderr together. Prefer spawning `bun run src/host/pair.ts` as a subprocess so
     this proves the real entry point, not just an exported function.
   - Assert the combined output **contains** `resolveBaseUrl(...)`.
   - Assert it contains a QR block character, i.e. a QR was actually rendered.
   - Assert it contains **no 8-character window of the dummy token** — iterate every window and
     report the count checked. Also assert it does not contain `encodeURIComponent(dummyToken)`
     and does not contain the full pairing URL.
   - Additionally run the **same check against the real token**: run the CLI with the real token
     file and assert no 8-character window of the **real** token appears in its output.
     **Print only the number of windows checked and the PASS verdict — never the token, never
     any window of it, and never the CLI's raw output in this sub-check.**

- Strict TypeScript: `strict` + `noUncheckedIndexedAccess` are on and `bunx tsc --noEmit`
  **must exit 0**. Real guards for possibly-undefined indexed reads; no `any`.
