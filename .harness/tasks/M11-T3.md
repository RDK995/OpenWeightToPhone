Acceptance Criteria:
- `web/src/credential-store.ts` exports:
  ```ts
  export interface LocationPort {
    readonly hash: string;    // e.g. "#t=abc123" or "" when absent
    readonly origin: string;  // e.g. "https://host.example"
    clearHash(): void;
  }
  export function adoptCredentialFromFragment(
    store: CredentialStore,
    location: LocationPort
  ): Credential | null;
  ```
- Behaviour:
  - Parses the fragment after the leading `#` as `application/x-www-form-urlencoded`
    parameters (use `URLSearchParams`), so both `#t=abc` and `#a=1&t=abc` yield `abc`.
  - Percent-encoded values are decoded (`URLSearchParams` does this), so a token written by
    `encodeURIComponent` round-trips byte-for-byte.
  - On a non-empty `t`: calls `store.setCredential({ baseUrl: location.origin, token })`,
    then `location.clearHash()`, then returns the stored `Credential`.
  - When no `t` parameter is present at all (including `hash === ""` and `hash === "#"`):
    returns `null` and **does not** call `clearHash()` and **does not** touch storage.
  - **Security rule — when a `t` parameter IS present but its value is empty or
    whitespace-only, or `setCredential` throws: still call `location.clearHash()`, then
    return `null`.** A credential that reached the fragment must never be left sitting in
    the URL and the page's history, even on the failure path. Make this explicit in the code
    and assert it in tests.
  - Does not overwrite an existing stored credential when the fragment carries no token.
    When the fragment DOES carry a token it replaces whatever was stored — a fresh scan wins.
- No DOM globals: the file must not reference `document`, `window`, or `localStorage`.
