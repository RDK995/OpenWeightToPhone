Goal:
Implement GF(256) arithmetic and Reed-Solomon error-correction codeword generation as
used by QR codes, in a new module `src/qr/reed-solomon.ts`. This is pure maths with no
knowledge of QR layout, versions, or pairing.

Relevant Requirements:
Milestone M11, architecture component **C2 — QR Encoder** (`src/qr/`, "Encode text into a
QR matrix and render it for a terminal", depends on nothing). This task builds the ECC
half of C2 only. A later task builds the encoder that consumes it.

Acceptance Criteria:
- `src/qr/reed-solomon.ts` exports:
  - `gfMul(a: number, b: number): number` — multiplication in GF(256).
  - `generatorPoly(degree: number): Uint8Array` — the QR generator polynomial of the given
    degree, coefficients highest-order first, length `degree + 1`, leading coefficient 1.
  - `rsEncode(data: Uint8Array, ecLen: number): Uint8Array` — returns **exactly** `ecLen`
    error-correction codewords for `data`.
- The field is GF(256) with QR's primitive polynomial **0x11D** and generator element **2**.
- Exp/log tables are built once at module load, not per call.
- `rsEncode` does not mutate its `data` argument.
- `rsEncode` throws on `ecLen < 1`.
- Strict TypeScript: the repo uses `strict` and `noUncheckedIndexedAccess`, so every
  indexed read is possibly-undefined and must be handled without `any` and without
  non-null assertions where a real guard is cheap.

Tests:

It MUST include this **complete correctness oracle**, which is what makes this task
verifiable without trusting any remembered test vector:

1. **Field sanity.** For every `x` in 1..255, `gfExp[gfLog[x]] === x`. `gfMul(a,0) === 0`.
   `gfMul(a,1) === a`. `gfMul` is commutative over a spread of values.
2. **Generator polynomial shape.** For each `degree` in the QR set
   `[7,10,13,15,16,17,18,20,22,24,26,28,30]`, `generatorPoly(degree).length === degree + 1`
   and its first coefficient is `1`.
3. **The syndrome property — the real oracle.** For each `ecLen` in that same set, and for
   several different `data` buffers (including all-zero, all-0xFF, and pseudo-random of
   varying lengths), form the full codeword `[...data, ...rsEncode(data, ecLen)]` read as a
   polynomial with the FIRST byte as the highest-order coefficient. Evaluate that
   polynomial in GF(256) at `alpha^i` for `i = 0 .. ecLen-1`. **Every one of those
   evaluations must be exactly 0.** That is the defining property of a Reed-Solomon
   codeword and it holds if and only if the encoder is correct, so do not weaken or skip it.
4. `rsEncode` returns length `ecLen` exactly, and leaves `data` unmodified.
