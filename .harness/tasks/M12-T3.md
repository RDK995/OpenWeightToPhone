## What to change

`web/src/ui/dom-target.ts`'s send handler currently calls `actions.send(selectedId, prompt)`
with two arguments. Give it a third: a `GenerationHandlers` object (defined in
`web/src/session-coordinator.ts`) built per send, wired as follows.

Keep a per-send local accumulator `let streamed = ""` and a local `let announcedStreaming =
false`. Then:

- **on send start**, before calling `actions.send`: `controller.setStreamingText("")` and
  `controller.setGeneration({ kind: "streaming" })`.
  Hmm — read the note below before implementing this line.
- `onQueued(position)` -> `controller.setGeneration({ kind: "queued", position })`
- `onModelLoading()` -> `controller.setGeneration({ kind: "model-loading" })`
- `onDelta(delta)` -> `streamed += delta`; if `!announcedStreaming` then
  `announcedStreaming = true; controller.setGeneration({ kind: "streaming" })`;
  then `controller.setStreamingText(streamed)`
- `onComplete(telemetry)` -> in THIS order:
  1. `controller.render()` — re-reads the store, so the assistant turn the coordinator just
     persisted enters the transcript
  2. `controller.setStreamingText("")` — drops the in-flight projection
  3. `controller.setGeneration({ kind: "complete", telemetry: toTelemetryDisplay(telemetry) })`
     (`toTelemetryDisplay` is exported from `web/src/ui/view-model.ts`)
- `onCancelled()` -> `controller.render()`, `controller.setStreamingText("")`,
  `controller.setGeneration({ kind: "cancelled" })`
- `onError(code, error)` -> `controller.setStreamingText("")`, then
  `controller.setGeneration({ kind: "error", code, message })` where `message` is the
  human-readable message on `HarnessStreamError`. **Read `web/src/sse-reader.ts` for
  `HarnessStreamError`'s real shape and use its actual field** — do not invent one, and do
  not use `String(error)`.

**Note on the "on send start" line and on `onComplete` ordering.** The requirement that
actually matters, and that your tests must prove, is: while deltas arrive the transcript
shows the growing text, and after `complete` the transcript shows the final assistant text
**exactly once** (not duplicated between the store's turn and the streaming projection)
alongside the rendered telemetry. `web/src/ui/view-model.ts` projects a pending transcript
entry from `state.streamingText`, falling back to the conversation's `pending.partialText`.
**Read `web/src/session-coordinator.ts` to find out whether the assistant turn is persisted
to the store before or after `onComplete` fires**, and adjust the ordering above if the real
behaviour makes it produce a duplicate or a flash of empty transcript. If you deviate from
