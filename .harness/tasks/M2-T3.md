Goal:
Implement C5 — Credential Store, limited to the half this milestone needs: holding a
`{ baseUrl, token }` credential and persisting it through the Storage Port.

**Explicitly out of scope for this task:** capturing the token from a URL fragment and
clearing `location.hash`. That is milestone M11 / acceptance criterion AC2 and belongs to a
later task. Do NOT touch `location`, `window`, or any DOM global. This module must be
importable and fully testable in a plain Bun process with no DOM.

Relevant Requirements:
- Architecture C5 — Credential Store. Location: `web/src/credential-store.ts`. Depends on: C11.
- Architecture Data: "`Credential` — `{ baseUrl, token }`. Owned by C5, persisted through C11."
- Architecture interface "C7 → C5": `getToken(): string | null`.
- Architecture interface "C8 → C11 and C5 → C11": `get(key)`, `set(key, value)`, `remove(key)`.

Acceptance Criteria:
- `web/src/credential-store.ts` exports a type `Credential` = `{ baseUrl: string; token: string }`.
- It exports `createCredentialStore(storage: StoragePort): CredentialStore`, importing
  `StoragePort` as a type from `./storage-port`.
- `CredentialStore` has exactly: `getCredential(): Credential | null`,
  `getToken(): string | null`, `setCredential(credential: Credential): void`,
  `clear(): void`.
- The credential is persisted under a single **versioned** storage key. Export that key as
  a named constant so tests and later milestones can refer to it rather than a string
  literal. Use the form `phone-to-local-model:v1:credential`.
- `setCredential` then `getCredential` round-trips both fields exactly, through the storage
  port only (a second store constructed over the *same* `StoragePort` must see the value —
  prove this in a test; it is what makes the browser reload case work).
- `getCredential` returns `null` when nothing is stored.
- `getCredential` returns `null` rather than throwing when the stored value is not valid
  JSON, or is JSON that lacks a string `baseUrl` or a string `token`. Corrupt storage must
  degrade to "not paired", never crash the app.
- `getToken` returns the token, or `null` when there is no valid credential.
- `clear()` removes the key; `getCredential()` returns `null` afterwards.
- `setCredential` normalises `baseUrl` by stripping trailing slashes (`https://h/` stores as
  `https://h`), matching `resolveBaseUrl` in `src/host/config.ts`. An empty `token` or an
  empty `baseUrl` is rejected by throwing — a blank credential is a bug, not a state.
