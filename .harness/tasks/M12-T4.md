## What to change in `web/src/main.ts`

Inside `bootstrap()`, replace the final `mount(...)` call with:

```ts
const target = resolvedCreateTarget(root);
const handle = mount({ target, coordinator, store });

// The DOM target is constructed before mount(), so the actions map and the
// controller can only be supplied afterwards.
if ("attach" in target && typeof (target as DomTarget).attach === "function") {
  (target as DomTarget).attach({ actions: handle.actions, controller: handle });
}

// Populate the profile selector. Fire-and-forget: a failure here must never
// stop the app mounting, and error surfacing is not this milestone's scope.
coordinator
  .listProfiles()
  .then((profiles) => handle.setProfiles(profiles))
  .catch(() => {});

return handle;
```

and change the signature to `export function bootstrap(root: HTMLElement, deps?:
BootstrapDeps): MountHandle`.

Notes on that sketch — implement its intent, not its letter:
- The `"attach" in target` guard exists because `BootstrapDeps.createTarget` lets a test
  inject a plain `RenderTarget` that has no `attach`. Existing tests do exactly that, and
  they must keep passing. Use whatever narrowing keeps `tsc --noEmit` clean under
  `strict` + `verbatimModuleSyntax`.
- `MountHandle` and `DomTarget` must be imported as **types** (`import type`) where possible.
- Also export `type MountHandle` and `type DomTarget` from `main.ts` alongside the existing
  re-exports, so the bundle test can reach them.
- The top-level browser bootstrap block (`if (typeof document !== "undefined")`) already
  calls `bootstrap(root)`; leave it working. It may ignore the returned handle.
- Do NOT let any top-level statement outside the `typeof document !== "undefined"` guard
  touch `document`, `window` or `localStorage` — `test/web/ui/bundle-mount.test.ts` depends on
  importing this module in a non-browser process without throwing.
