# Task M11-T8 — Wire fragment credential adoption into the browser entry point

Tier: **Cheap**. Reason for going above Cheap: **none named**. The change is clearly
specified below (exact signatures given), bounded to three named files, backed by a total
oracle (`bun test` + `bunx tsc --noEmit`, with assertions that fail if the wiring is removed),
and cheap to be wrong about.

## Context

`web/src/credential-store.ts` exports `adoptCredentialFromFragment(store, location)` and the
`LocationPort` interface. The function is correct and fully tested — **do not change it.**

The defect: **nothing in the app ever calls it.** `bootstrap()` in `web/src/main.ts` does not,
so the bundler tree-shakes the function out entirely — `web/dist/main.js` contains zero
occurrences of `adoptCredentialFromFragment` and zero of `location.hash`. On a real iPhone,
opening the app at `#t=<token>` is indistinguishable from opening it without: the scan does
not pair the phone. This was falsified by a human on the physical device.

There is a second, latent defect in the same function. `bootstrap()` currently does:

```ts
const credential = credentialStore.getCredential();
const apiClient = createApiClient({
  baseUrl: credential?.baseUrl ?? "",
  getToken: () => credentialStore.getToken(),
});
```

`baseUrl` is **captured once at construction** from a credential read before any adoption could
have happened. So adopting *after* this point would still leave the client with an empty base
URL. Adoption must happen **before** the credential is read for `baseUrl`.

## Goal

1. Add a real `LocationPort` over `window.location` whose `clearHash()` removes the fragment
   **without adding a history entry and without reloading the page**.
2. Make `bootstrap()` adopt the credential from that location **before** it constructs the API
   client, so a phone opening `/app/#t=<token>` is paired.
3. Add tests that **fail if the adoption call is removed from `bootstrap()`** — not tests that
   call the adopter directly. Calling the adopter directly is exactly what 711 existing tests
   already do, and it is why this defect shipped.

## Required design

### `web/src/location-port.ts` (new)

Mirror the shape of `web/src/storage-port.ts` (a port module with a memory/fake-friendly
surface plus a real adapter). It must import the `LocationPort` **type** from
`./credential-store` — do not redefine or move the interface, because `src/host/m11-proof.ts`
and `test/web/credential-store.test.ts` import it from there and must keep working.

Export:

```ts
export function createWindowLocation(win: Window): LocationPort
```

- `hash` and `origin` are **live getters** delegating to `win.location.hash` and
  `win.location.origin` — not values snapshotted at construction. A snapshot would read stale
  after `clearHash()`.
- `clearHash()` must remove the fragment using
  `win.history.replaceState(null, "", <path+search>)`, i.e. `replaceState`, never
  `pushState`, never assignment to `win.location.hash` or `win.location.href`
  (assignment adds a history entry; `location.hash = ""` also leaves a bare trailing `#` in
  the URL bar and can trigger a hashchange/scroll).
- The replacement URL must preserve `pathname` and `search` and drop only the fragment. For
  `https://host/app/?a=1#t=x` the replacement is `/app/?a=1`.
- If `win.history` or `win.history.replaceState` is unavailable, fall back to
  `win.location.replace(<url without fragment>)` if available, and otherwise do nothing rather
  than throwing. `clearHash()` must never throw: a thrown error here would abort bootstrap and
  leave the token visible in the URL, which is worse than a fragment that lingers.
- The module must not reference the `window`/`document`/`localStorage` **globals** — it takes
  `win` as a parameter, so importing it in a non-browser process must never throw.

### `web/src/main.ts` (modify)

Change `bootstrap` to:

```ts
export interface BootstrapDeps {
  storage?: StoragePort;
  location?: LocationPort;
  createTarget?: (root: HTMLElement) => RenderTarget;
  createApiClient?: typeof createApiClient;
}

export function bootstrap(root: HTMLElement, deps?: BootstrapDeps): void
```

Every dependency is optional and **defaults to exactly the production collaborator it uses
today**:

- `storage` → `createLocalStorageStorage(window.localStorage)`
- `location` → `createWindowLocation(window)`
- `createTarget` → `createDomTarget`
- `createApiClient` → the imported `createApiClient`

Defaults must be resolved **lazily, only when the corresponding dep is absent**. A test process
has no `window` global at all, so `bootstrap(root, { storage, location, createTarget,
createApiClient })` must complete without ever evaluating `window`. Do not write
`deps?.storage ?? createLocalStorageStorage(window.localStorage)` — that evaluates the fallback
eagerly and throws. Use an explicit `if (deps?.x !== undefined) … else …` or equivalent.

The body must run in this order:

1. resolve `storage`, build `conversationStore` and `credentialStore`
2. **`adoptCredentialFromFragment(credentialStore, location)`** — the resolved `LocationPort`
3. **then** `const credential = credentialStore.getCredential()`
4. `createApiClient({ baseUrl: credential?.baseUrl ?? "", getToken: () => credentialStore.getToken() })`
5. coordinator, target via `createTarget(root)`, `mount(...)`

Keep the existing behaviour that a missing credential is not an error — bootstrap must still
mount and paint with an empty base URL when there is no fragment and no stored credential.

The existing `typeof document !== "undefined"` top-level block calls `bootstrap(root)` with no
deps and must stay exactly as it is. Also keep the existing `export { mount, createDomTarget,
createActions, buildViewModel, toTelemetryDisplay }` line, and **add `createWindowLocation`,
`adoptCredentialFromFragment` and `createCredentialStore` to the bundle's exported surface** —
a later task asserts against the built bundle, and the export keeps the code reachable for that
assertion as well as being genuinely useful to the proof.

Update the file's header comment to say that bootstrap adopts a pairing fragment before it
constructs the API client, and why the order matters.

## Tests (Red → Green → Refactor)

Write the failing test first, watch it fail for the right reason, then implement.

### `test/web/location-port.test.ts`

Drive `createWindowLocation` with a hand-written fake `Window` (an object literal cast as
needed — do not install globals). Cover:

- `hash` and `origin` read through to `win.location` and are **live**: mutate
  `win.location.hash` after construction and observe the port reflect the new value.
- `clearHash()` calls `win.history.replaceState` **exactly once**, with a URL that has no `#`,
  preserves `pathname` and `search`, and is passed as the third argument.
- `clearHash()` calls neither `pushState` nor `location.assign`/`location.replace` when
  `replaceState` is available, and never assigns to `location.hash` or `location.href`
  (assert via a setter spy on the fake).
- `clearHash()` does not throw when `win.history` is absent, and does not throw when
  `replaceState` is absent.
- A round trip: with hash `#t=abc`, after `clearHash()` (with a fake `replaceState` that
  updates the fake location) the port's `hash` reads `""`.

### `test/web/main-bootstrap.test.ts` — the proof that would fail if the call were removed

Import `bootstrap` from `../../web/src/main` and call it with **injected** `storage`,
`location`, `createTarget` and `createApiClient`. Assert first that `typeof document ===
"undefined"` in this process, so the import is genuinely exercising the non-browser guard.

Use `createMemoryStorage()` from `web/src/storage-port` and a hand-written fake `LocationPort`.
`createTarget` returns a trivial `RenderTarget` that records paints (see
`test/web/ui/bundle-mount.test.ts` for the shape). `createApiClient` is a stub that **records
the `baseUrl` it was constructed with** and returns an object satisfying the `ApiClient` type
(methods may throw if called — check what `createSessionCoordinator` needs at construction and
during `mount`, and stub just enough that `bootstrap` returns without throwing).

Required assertions:

1. **Adoption happens.** With storage empty and location `{ hash: "#t=tok-abc", origin:
   "https://example.test" }`, after `bootstrap(fakeRoot, deps)` the storage holds a credential
   with `token === "tok-abc"` and `baseUrl === "https://example.test"`. *This is the assertion
   that fails if the call is removed from `bootstrap()` — say so in a comment.*
2. **The hash is cleared.** The fake location's `clearHash()` was called, and its `hash` reads
   `""` afterwards.
3. **The API client gets the adopted base URL — the ordering proof.** The recorded
   `baseUrl` passed to the injected `createApiClient` is `"https://example.test"`, **not**
   `""`. *This assertion fails if adoption is moved after the client is constructed — say so
   in a comment.* Also assert the client's `getToken()` returns `"tok-abc"`.
4. **A fragment with `a=1&t=tok` also pairs** (the adopter parses with `URLSearchParams`).
5. **No fragment, no stored credential:** `bootstrap` does not throw, paints at least once,
   the API client is constructed with `baseUrl === ""`, storage still holds no credential, and
   `clearHash()` was **not** called.
6. **No fragment, credential already stored:** the stored credential survives untouched and
   the API client is constructed with the **stored** `baseUrl`.
7. **A fragment overrides nothing it should not:** with `#t=new` and an existing stored
   credential, the new token wins and the hash is cleared (this matches the adopter's
   documented behaviour — confirm against `test/web/credential-store.test.ts` rather than
   assuming, and assert whatever the adopter actually specifies).

Do not weaken, skip, delete or `try/catch`-swallow any assertion. If something cannot be
asserted, say so in your return rather than writing a test that cannot fail. A test that
catches its own failure and returns is treated as a FAIL for this task.

## Acceptance Criteria

- AC-T8.1 `web/src/location-port.ts` exports `createWindowLocation(win)` returning a
  `LocationPort` with live `hash`/`origin` and a `clearHash()` that uses
  `history.replaceState`, adds no history entry, causes no reload, and never throws.
- AC-T8.2 `bootstrap()` calls `adoptCredentialFromFragment` with a `LocationPort` over the real
  `window` (by default) **before** it reads the credential for the API client's `baseUrl`.

  with no `window` and no `document` global.

  `localStorage`, `window.location`, `createDomTarget` and `createApiClient`.
