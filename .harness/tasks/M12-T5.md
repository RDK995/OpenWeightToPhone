## What "through the UI's own send path" means here

It is not enough to call `coordinator.send(...)`. M2 already proved that. This proof must go
in at the DOM:

- build a happy-dom `Window` and a root element
- call the **real** `createDomTarget(root)` from `web/src/ui/dom-target.ts`
- construct the **real** `createApiClient` with the **real** token and base URL read from
  `src/host/config.ts` (`readToken(env)` / `resolveBaseUrl(env)` — read that file for the
  exact exports and semantics; note it refuses a group- or world-readable token file)
- construct the **real** `createSessionCoordinator` over a real `ConversationStore` backed by
  the in-memory `StoragePort`
- `mount(...)` and `target.attach({ actions: handle.actions, controller: handle })`
- then drive it by DOM events only: populate the profile selector, click
  `create-conversation`, click that conversation's `open-conversation`, set `prompt-input`'s
  value, and `dispatchEvent(new w.Event("click"))` on `send`

## What it must assert and print

- **Incrementality is the point.** Record the transcript text out of the DOM on each repaint
  and assert it grew in **more than one** step — a single jump from empty to the full answer
  means nothing was streamed, and the proof must FAIL in that case. Print the observed number
  of distinct growth steps and the first few prefixes.
- Assert the final DOM status region renders the completion telemetry: tokens/sec, eval
  count, quantization and context limit (see `generationStatusText` in `dom-target.ts`).
  Print the rendered status line verbatim.
- Exit non-zero with a clear message on any failure, including an unreachable harness or a
  refused token. Exit 0 only when every assertion held.
- Print the profile id used and the prompt sent, so a human reading the output can see what
  was actually proven.
