Acceptance Criteria:

**Part A — `src/host/serve-install.ts`** (pure and injectable; no top-level side effects):

1. Types: `ServeHandler = { path: string; proxy: string | null }` and a
   `ServeStatus` shape matching the JSON above (be tolerant: `Web`, the host key, and
   `Handlers` may all be missing).
2. `export function findHandlers(status: ServeStatus, mountPath: string): { root: ServeHandler | null; app: ServeHandler | null; hostKey: string | null }`
   — locates the `/` handler and the `mountPath` handler across whatever host key is
   present. Do not hardcode the hostname.
3. `export function planServeInstall(status: ServeStatus, opts: { port: number; mountPath: string }): ServePlan`
   where `ServePlan = { action: "noop" | "apply"; reason: string; command: string[];
   root: ServeHandler | null; app: ServeHandler | null }`.
   - Expected target is `` `http://127.0.0.1:${port}` ``.
   - If the `mountPath` handler exists and its proxy already equals the expected target:
     `action: "noop"`, `command: []`. **This is the idempotence requirement** — re-running
     must not invoke `tailscale` at all.
   - Otherwise `action: "apply"` with
     `command: ["tailscale", "serve", "--bg", "--set-path", mountPath, expectedTarget]`.
   - The produced `command` must NEVER contain `reset`, `clear`, `drain`, `off`, or
     `--funnel`, and must never target any path other than `mountPath`. Enforce this with
     an assertion inside the function that throws if violated, not only by construction.
4. `export function diagnose(status: ServeStatus, opts: { port: number; mountPath: string }): { ok: boolean; exitCode: number; lines: string[] }`
   Human-readable, one fact per line. Exit codes, exactly:
   - `0` — `mountPath` handler present and pointing at the expected target.
   - `3` — `mountPath` handler ABSENT. The lines MUST include the literal
     `tailscale serve --bg --set-path <mountPath> http://127.0.0.1:<port>` command a human
     can copy, and must say plainly that until it is applied,
     `https://<host>/app/` will be proxied to the harness and return `401`.
   - `4` — `mountPath` handler present but pointing somewhere else; the lines must state
     both the found target and the expected one.
   The lines must always also report whether the `/` handler is present and what it proxies
   to, because that is the handler a mistake would destroy.
5. `export async function runServeInstall(opts: { mode: "check" | "apply"; port: number; mountPath: string; dryRun?: boolean; exec: Exec }): Promise<{ exitCode: number; lines: string[] }>`
   where `export type Exec = (argv: string[]) => Promise<{ code: number; stdout: string; stderr: string }>`.
   - Always begins by running `["tailscale","serve","status","--json"]` through `exec` and
     parsing it. If that call fails or the JSON does not parse, exit code `6` with lines
     explaining that the serve configuration could not be read.
   - `mode: "check"` never runs anything but the status read. It returns `diagnose(...)`.
   - `mode: "apply"`:
     - Computes the plan. If `action` is `"noop"`, returns exit code `0` with a line saying
       the mapping is already correct, **without calling `exec` again**.
     - If `dryRun`, prints the command it would run and returns `0` **without calling
       `exec` again**.
     - Otherwise runs the plan's command through `exec`. If it exits non-zero, return exit
       code `6` with lines containing the command's stderr AND the exact command line the
       human must run themselves. Authorisation failures are expected here and must be
       reported clearly, never retried with `sudo` and never worked around.
     - Then re-reads the status and **verifies both**: the `mountPath` handler is now
       present and correct, AND the `/` handler is still present with the same proxy target
       it had before the apply. If `/` changed or vanished, return exit code `5` with a
       prominent line and the exact command to restore it
       (`tailscale serve --bg --set-path / <original target>` — state it using the original
       target captured before the apply). If `mountPath` is still absent, return `3`.
     - On full success return `0`.
6. `import.meta.main` entry: parse argv supporting `check` (the default when no subcommand
   is given), `apply`, and the flags `--dry-run`, `--port <n>`, `--mount <path>`, `--help`.
   Defaults come from `resolvePwaPort()` and `APP_MOUNT_PATH` in `./config.ts`. Print the
   returned lines and `process.exit(exitCode)`. The real `Exec` implementation uses
   `Bun.spawn`. **`check` must be the default** so that running the script with no
   arguments cannot change anything.

**Part B — `deploy/install-serve.sh`**, a thin POSIX-sh wrapper, `chmod +x`:
- Resolves the repository root from its own location (`dirname "$0"/..`), not from `cwd`.
- Resolves bun as `${BUN_BIN:-$HOME/.bun/bin/bun}`, falling back to `bun` on `PATH`; if
  neither is executable, print a clear message naming `~/.bun/bin/bun` and exit `7`.
- `exec` s `"$BUN" run "$ROOT/src/host/serve-install.ts" "$@"` so the exit code passes
  through unchanged.
- Contains no `tailscale` invocation of its own — all logic lives in the TypeScript module
  so it is testable.
- Must not contain the strings `sudo`, `serve reset`, or `serve clear`.

**Part C — `test/host/serve-install.test.ts`** (`bun:test`), covering at minimum:
- `findHandlers` against the real status JSON quoted above: root found with proxy
  `http://127.0.0.1:7787`, app `null`.
- `diagnose` on that status returns `exitCode: 3` and lines containing the copyable
  `tailscale serve --bg --set-path /app http://127.0.0.1:7788` command and the `401`
  explanation, and reporting the `/` handler.
- `diagnose` returns `0` when `/app` is present and correct, `4` when it points elsewhere.
- `planServeInstall` returns `noop` with an empty command when already correct.
- `planServeInstall`'s command never contains `reset`, `clear`, `drain`, `off`, `--funnel`
  or `sudo` — assert over the joined argv.
- `runServeInstall` with `mode:"check"` and a **spy exec** calls `exec` exactly once, with
  `["tailscale","serve","status","--json"]`.
- `runServeInstall` with `mode:"apply"` against an already-correct status calls `exec`
  exactly once (idempotence: no mutation).
- `runServeInstall` with `mode:"apply", dryRun:true` against the absent status calls `exec`
  exactly once and returns `0`.
- `runServeInstall` with `mode:"apply"` against the absent status, with a fake exec that
  records the apply and then returns a status where `/app` is correct and `/` unchanged:
  returns `0`, and the recorded argv is exactly
  `["tailscale","serve","--bg","--set-path","/app","http://127.0.0.1:7788"]`.
- The `/`-destroyed path: fake exec returns a post-apply status in which `/` is missing →
  returns exit code `5` and the lines include a restore command naming
  `http://127.0.0.1:7787`.
- The authorisation-refused path: fake exec returns `{code:1,stderr:"access denied"}` for
  the apply → exit code `6`, lines contain `access denied` and the copyable command.
- A malformed status JSON → exit code `6`.
- Read `deploy/install-serve.sh` as text and assert it contains none of `sudo`,
  `serve reset`, `serve clear`.
**No test may invoke the real `tailscale` binary.** Every test injects `exec`.
