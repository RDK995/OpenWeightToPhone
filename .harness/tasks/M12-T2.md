## The contract you must implement

Today `createDomTarget(root: HTMLElement): RenderTarget` paints four read-only sections.
Change it to:

```ts
export interface DomController {
  render(): void;
  select(conversationId: string | null): void;
  setGeneration(generation: GenerationDisplay): void;
  setStreamingText(text: string): void;
  setProfiles(profiles: readonly Profile[]): void;
}

export interface DomTarget extends RenderTarget {
  attach(deps: { actions: UiActions; controller: DomController }): void;
}

export function createDomTarget(root: HTMLElement): DomTarget;
```

`DomController` is deliberately structurally satisfied by the existing `MountHandle` in
`web/src/ui/mount.ts` — do not change `MountHandle`. `attach()` exists because the target is
constructed *before* `mount()` runs (mount takes the target as a dependency), so the actions
map and the handle can only be supplied afterwards. Before `attach()` is called, a dispatched
event must be a harmless no-op — never a throw.

## Controls, and their exact event-to-action mapping

Every control carries a `data-testid` attribute with EXACTLY the value given. Tests address
controls by `data-testid`; do not rename them.

| `data-testid` | element | event | must invoke |
| --- | --- | --- | --- |
| `prompt-input` | `textarea` | — | (holds the draft) |
| `send` | `button` | `click` | `actions.send(selectedId, promptText)` |
| `cancel` | `button` | `click` | `actions.cancel(selectedId)` |
| `profile-select` | `select` | `change` | `actions.chooseProfile(selectedId, value)` |
| `create-conversation` | `button` | `click` | `actions.createConversation({ profileId })` |
| `open-conversation` | `button`, one per conversation list item | `click` | `controller.select(id)` |
| `delete-conversation` | `button`, one per conversation list item | `click` | `actions.deleteConversation(id)` |

Rules that go with the table:

- `selectedId` is the id of the currently selected conversation, which the target learns from
  the `ViewModel` it was last painted with (the list item whose `selected` is `true`). If
  there is no selected conversation, `send`, `cancel` and `profile-select` make **no call at
  all** — a silent no-op, not a throw.
- `promptText` is the raw current value of `prompt-input` **trimmed**. See the empty-prompt
  rule below.
- `create-conversation` uses the current value of `profile-select` as `profileId`. If that
  value is empty (no profiles yet), it makes **no call at all**.
- `open-conversation` and `delete-conversation` buttons are rendered per conversation inside
  `paint()`, and each must carry `data-conversation-id="<that conversation's id>"` so a test
  can find the right one. They must act on **their own** conversation's id, not the selected
  one.
- After a successful `actions.send(...)`, clear `prompt-input`'s value. Do NOT clear it when
  the send was rejected (see below). Handle the returned promise so an eventual rejection
  cannot become an unhandled rejection — `.catch(() => {})` is acceptable here; error
  surfacing is not this task's scope.
- **`open-conversation` calling `controller.select` is correct and intended.** Selecting is
  pure UI state and reaches no service. Do not route it through the actions map.

## Empty-prompt rejection (criterion 4)

On `send` click, if the trimmed value of `prompt-input` is the empty string:
- make **no** `actions.send` call (and no other action call, and no `fetch`),
- leave `prompt-input`'s value **exactly as the user typed it** — do not trim it in place, do
  not clear it. `"   "` must still read `"   "` afterwards.
- Return without throwing.

## The actions map needs a delete

`UiActions` in `web/src/ui/actions.ts` has no delete, and the delete control must not reach
C8 directly ("No control reaches C7, C8 or C9 except through the actions map"). So:

- Add `deleteConversation(conversationId: string): void` to the `UiActions` interface.
- Change `createActions(coordinator: SessionCoordinator)` to
  `createActions(coordinator: SessionCoordinator, store: ConversationStore)`, implementing
  `deleteConversation` as `store.deleteConversation(conversationId)`.
- Update the single call site in `web/src/ui/mount.ts` (`actions: createActions(coordinator)`)
  to pass the store it already holds: `createActions(coordinator, store)`.
- `mount.ts` must NOT gain a runtime import of `./dom-target` — `test/web/ui/mount.test.ts`'s
  "no bypass access" suite asserts this over the file text, and it must keep passing.
