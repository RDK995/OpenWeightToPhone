Endpoint facts, quoted from the harness API document
(`/Users/ryankenny/Projects/OpenCodeOpenWeightHarness/docs/api/phone-reasoning-surface-v1.md`,
which you may read but must never modify):

- `GET /v1/profiles` → 200, body `{"api_version":"v1","profiles":[{ "id", "role",
  "quality", "latency_class", "label" }, ...]}`
- `POST /v1/sessions` → **201**, body `{"api_version":"v1","session_id":"...",
  "created_at":"...","turns":[]}`. Send `Content-Type: application/json` with body `{}`.
  Note the status is 201, not 200.
- `GET /v1/sessions/{session_id}` → 200, body
  `{"api_version":"v1","session_id","created_at","turns":[{ "index","role","content",
  "created_at","cancelled" }],"generations":[{ "generation_id","status","last_seq",
  "created_at" }]}`. `status` is one of `queued|in_flight|complete|failed|cancelled`.
- `POST /v1/sessions/{session_id}/generate` → 200, a `text/event-stream` response carrying
  the generation id in the **`x-generation-id` response header**. Request body:
  `{"profile_id": "<id>", "prompt": "<text>"}`. Both fields required; empty prompt is an error.
- Error bodies are JSON `{"api_version":"v1","error":"<code>"}`. Documented codes and
  statuses, verbatim: `unauthorized` 401, `invalid_request` 400, `unknown_session` 404,
  `unknown_profile` 400, `generation_in_flight` 409, `queue_full` 503,
  `unknown_generation` 404, `seq_not_available` 409 (body also includes `last_seq`),
  `not_found` 404, `internal_error` 500.

Acceptance Criteria:
- `web/src/api-client.ts` exports `createApiClient(options): ApiClient` where `options` is
  `{ baseUrl: string; getToken: () => string | null; fetch?: typeof fetch }`. The `fetch`
  option defaults to the global `fetch` and exists so tests can stub it — tests MUST use the
  stub and make no network call.
- Every request carries `Authorization: Bearer <token>` using the token from `getToken()` at
  **call time**, not captured at construction time (the token can change after re-pairing).
  If `getToken()` returns `null`, throw a `HarnessApiError` with code `unauthorized` without
  making a request.
- It exports `class HarnessApiError extends Error` with readonly fields `code: string`,
  `status: number`, and `body: unknown`. Any non-OK HTTP response is converted into one,
  taking `code` from the response body's `error` field, or falling back to
  `http_<status>` when the body is not JSON or has no `error` field. It must never throw a
  bare `Error` for an HTTP failure.
- `listProfiles(): Promise<Profile[]>` — `GET {baseUrl}/v1/profiles`, returns the `profiles`
  array. Export a `Profile` type with the five documented fields; tolerate extra fields.
- `createSession(): Promise<string>` — `POST {baseUrl}/v1/sessions` with
  `Content-Type: application/json` and body `{}`; accepts **201** as success and returns
  `session_id`. A 200 must also be accepted (`response.ok`), but the test must cover 201
  specifically because that is what the live service returns.
- `getSession(sessionId: string): Promise<SessionSnapshot>` —
  `GET {baseUrl}/v1/sessions/{sessionId}`. Export `SessionSnapshot`, `SessionTurn` and
  `SessionGeneration` types matching the documented shapes; tolerate extra fields.
- `generate(sessionId, { profileId, prompt }): Promise<{ generationId: string; events: AsyncIterable<HarnessEvent> }>`
  — `POST {baseUrl}/v1/sessions/{sessionId}/generate` with `Content-Type: application/json`,
  `Accept: text/event-stream`, and body `{"profile_id": profileId, "prompt": prompt}`.
  - It returns **as soon as the response headers arrive**, before the stream is consumed.
    `generationId` comes from the `x-generation-id` response header. `events` is
    `readEvents(response.body)` from `./sse-reader`. It must NOT buffer the stream — that
    would defeat AC3. Do not `await response.text()`.
  - Throws `HarnessApiError` with code `invalid_request` for an empty or whitespace-only
    prompt, **before making any request** (requirements Edge Cases: "An empty prompt is
    rejected client-side before a request is made").
  - Throws `HarnessApiError` if the response is not OK, or if `x-generation-id` is missing,
    or if `response.body` is null.
- **Request log.** The client records every HTTP request it issues, in order, and exposes
  `getRequestLog(): readonly LoggedRequest[]` where `LoggedRequest` is
  `{ method: string; url: string; at: string }` (`at` an ISO-8601 timestamp). The entry is
  appended at the moment the request is dispatched, for **every** request including ones
  that then fail. Also export `clearRequestLog(): void`.
  This log is the evidence instrument for a milestone acceptance criterion asserting the
  client never posts turns during a generation, so it must record honestly and
  unconditionally — one entry per outbound request, no exceptions and no filtering.
- A test asserts that after `createSession` + `generate` + `getSession`, `getRequestLog()`
  contains **no** entry whose URL contains `/turns`.
- There is no `appendTurn` method and no string `/turns` anywhere in `web/src/api-client.ts`.
