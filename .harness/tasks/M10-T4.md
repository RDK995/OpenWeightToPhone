Goal:
Add the launch agent (component C13): a module that renders the launchd property list for
the PWA asset server and installs/uninstalls it through an injected exec, plus a thin shell
wrapper, plus unit tests. Do not run launchctl.

Relevant Requirements:

Acceptance Criteria:
- New file `src/host/launch-agent.ts`. All logic lives here so it is testable with an
  injected exec — mirror the pattern already used by `src/host/serve-install.ts` (read it

- It exports at least:
    export const LAUNCH_AGENT_LABEL = "com.ryankenny.phone-pwa";
    export function launchAgentPlistPath(label: string, home: string): string;
      // `${home}/Library/LaunchAgents/${label}.plist`
    export function escapeXml(value: string): string;
    export function renderPlist(options: {
      label: string;
      bunPath: string;          // absolute path to the bun binary
      serverScript: string;     // absolute path to src/host/pwa-server.ts
      workingDirectory: string; // repository root
      port: number;
      bundleRoot: string;       // absolute path to web/dist
      stdoutPath: string;
      stderrPath: string;
    }): string;
- `renderPlist` returns a complete, valid XML property list: the `<?xml ...?>` declaration,
  the Apple `DOCTYPE` (`-//Apple//DTD PLIST 1.0//EN`, `http://www.apple.com/DTDs/PropertyList-1.0.dtd`),
  `<plist version="1.0">` and a top-level `<dict>` containing:
    Label                 → the label
    ProgramArguments      → array: [bunPath, "run", serverScript]
    WorkingDirectory      → workingDirectory
    EnvironmentVariables  → dict with `PHONE_PWA_PORT` (the port, as a string) and
                            `PHONE_PWA_BUNDLE_ROOT` (bundleRoot). These are the two env
                            names `src/host/config.ts` already reads — do not invent new
                            ones, and confirm the spelling by reading that file.
    RunAtLoad             → <true/>
    KeepAlive             → <true/>   (unconditional: the criterion is that it restarts
                                       after the process exits, including a clean exit and
                                       a SIGKILL)
    StandardOutPath       → stdoutPath
    StandardErrorPath     → stderrPath
    ProcessType           → "Background"
  Every interpolated string value must pass through `escapeXml` (at minimum `&`, `<`, `>`).
- It exports an install and an uninstall function taking injected collaborators so neither
  touches the real system in tests. Suggested shapes (adjust to match
  `src/host/serve-install.ts`'s conventions, which take precedence):
    export interface LaunchAgentDeps {
      writeFile: (path: string, contents: string) => Promise<void>;
      mkdir: (path: string) => Promise<void>;
      rm: (path: string) => Promise<void>;
      exec: (command: string, args: readonly string[]) => Promise<{ exitCode: number; stdout: string; stderr: string }>;
    }
    export async function installLaunchAgent(options: {...; uid: number; plistPath: string}, deps: LaunchAgentDeps): Promise<void>;
    export async function uninstallLaunchAgent(options: { label: string; uid: number; plistPath: string }, deps: LaunchAgentDeps): Promise<void>;
- `installLaunchAgent` must, IN THIS ORDER:
    1. mkdir the containing `LaunchAgents` directory (idempotent);
    2. write the rendered plist to `plistPath`;
    3. `launchctl bootout gui/<uid>/<label>` — tolerating a non-zero exit, because the
       agent legitimately may not be loaded yet. It must NOT throw on that failure;
    4. `launchctl bootstrap gui/<uid> <plistPath>` — a non-zero exit here IS a failure and
       must throw an error naming the command, the exit code and the captured stderr;
    5. `launchctl enable gui/<uid>/<label>` — tolerating a non-zero exit;
    6. `launchctl kickstart -k gui/<uid>/<label>` — a non-zero exit here IS a failure and
       must throw, as in step 4.
  Being re-runnable is required: running it twice in a row must succeed both times, which
  is why step 3 tolerates failure.
- `uninstallLaunchAgent` runs `launchctl bootout gui/<uid>/<label>` (tolerating non-zero)
  and then removes the plist file (tolerating absence).
- New file `deploy/install-launch-agent.sh`: a thin `#!/bin/sh` wrapper that resolves paths
  and `exec`s bun on `src/host/launch-agent.ts`, copied in structure from
  `deploy/install-serve.sh` (same `set -eu`, same `SCRIPT_DIR`/`ROOT` resolution, same
  `BUN_BIN` fallback chain and the same `exit 7` when bun is missing). Make it executable
  (`chmod +x`). `src/host/launch-agent.ts` therefore needs an `if (import.meta.main)` block
  that performs the real install with real collaborators (node:fs/promises + Bun.spawn or
  whatever `serve-install.ts` already uses), resolving bun's path, the repo root, the port
  via `resolvePwaPort()` and the bundle root via `resolveBundleRoot()` from
  `./config.ts`, and supporting an `--uninstall` argument. Writing that block is required;
  RUNNING it is forbidden in this task.
- New test file `test/host/launch-agent.test.ts` (Bun test, matching the conventions of the
  existing tests under `test/host/`) covering:
    * `renderPlist` output is a VALID plist — write it to a temp file and run
      `plutil -lint <file>` via `Bun.spawn`/`Bun.$`, asserting exit code 0. This is the
      real oracle for this task; do not skip it.
    * round-tripping: `plutil -convert json -o - <tempfile>` parses to an object whose
      `Label`, `ProgramArguments`, `RunAtLoad` (true), `KeepAlive` (true),
      `WorkingDirectory`, `ProcessType`, `StandardOutPath`, `StandardErrorPath` and
      `EnvironmentVariables.PHONE_PWA_PORT` / `.PHONE_PWA_BUNDLE_ROOT` all equal what was
      passed in.
    * XML escaping: a `workingDirectory` containing `&` and `<` still lints clean and
      round-trips back to the original unescaped string.
    * `launchAgentPlistPath("com.x.y", "/Users/z")` === `/Users/z/Library/LaunchAgents/com.x.y.plist`.
    * `installLaunchAgent` with a FAKE exec that records every `(command, args)` pair and a
      fake fs: asserts the recorded sequence is exactly bootout → bootstrap → enable →
      kickstart with the argument vectors specified above, that the plist was written to
      `plistPath` before the first exec, and that the written contents equal
      `renderPlist(...)`.
    * `installLaunchAgent` succeeds when the fake exec returns a NON-ZERO exit for
      `bootout` (and for `enable`), and REJECTS when the fake exec returns non-zero for
      `bootstrap`, and separately when it returns non-zero for `kickstart`. Assert the
      thrown message mentions the failing exit code and the captured stderr.
    * `uninstallLaunchAgent` issues `bootout` and removes the file, tolerating both a
      non-zero bootout and a missing file.
