Goal:
Implement C6 — SSE Reader. Turn a streaming response body into an ordered async sequence of

Relevant Requirements:
- Architecture C6 — SSE Reader: "Turn a streaming response body into an ordered sequence of
  typed harness events, tracking the last sequence number seen." Location:
  `web/src/sse-reader.ts`. Depends on: None.
- Architecture interface "C7 → C6": `readEvents(body: ReadableStream): AsyncIterable<HarnessEvent>`,
  where `HarnessEvent` is the union of `model-loading`, `content`, `queued`, `complete`,
  `error` and `cancelled`.
- Requirements constraint: "within `v1` the endpoint set is fixed and existing response
  fields are immutable, so the client may rely on documented fields but must tolerate new
  ones."

The wire format, quoted verbatim from the harness's own API document
(`docs/api/phone-reasoning-surface-v1.md`, lines 421-432):

    **SSE wire format:** Each event follows this exact block structure:

    id: <seq>
    event: <kind>
    data: <JSON event object>
    <blank line>

    - `id:` carries the sequence number for resumption
    - `event:` carries the event kind
    - `data:` carries the complete event as compact JSON, including `seq` and `kind`

The event table, quoted verbatim (lines 98-105):

    | Event | Fields | Terminal | Meaning |
    | `model-loading` | `seq`, `kind` | no | Model is being loaded |
    | `content` | `seq`, `kind`, `delta` | no | Incremental content from the model |
    | `queued` | `seq`, `kind`, `position` | no | Generation is waiting in the queue (position is 1-based) |
    | `complete` | `seq`, `kind`, `telemetry` | yes | Generation completed successfully |
    | `error` | `seq`, `kind`, `error` | yes | Generation encountered an error |
    | `cancelled` | `seq`, `kind` | yes | Generation was cancelled by the client |

The telemetry object, quoted verbatim (lines 447-467):

    { "profile_id": string, "quantization": string, "context_limit": number,
      "total_duration_ns": number, "load_duration_ns": number,
      "prompt_eval_count": number, "eval_count": number, "tokens_per_second": number }

Sequence guarantee, quoted verbatim (lines 586-591):

    - Sequence numbers start at 0 for a generation's first event
    - They increase by exactly 1 per event
    - They are unique within a generation (never reused)

Acceptance Criteria:
- `web/src/sse-reader.ts` exports these types:
  - `Telemetry` — an object type with the eight fields listed above, in their documented
    types. It must be an interface or type that does NOT forbid extra properties (tolerate
    new fields).
  - `HarnessEvent` — a discriminated union on `kind` with exactly these six members:
    `{ seq: number; kind: "model-loading" }`,
    `{ seq: number; kind: "content"; delta: string }`,
    `{ seq: number; kind: "queued"; position: number }`,
    `{ seq: number; kind: "complete"; telemetry: Telemetry }`,
    `{ seq: number; kind: "error"; error: string }`,
    `{ seq: number; kind: "cancelled" }`.
  - A `TERMINAL_KINDS` export (a readonly set or array) naming exactly `complete`, `error`
    and `cancelled`, and a helper `isTerminal(event: HarnessEvent): boolean`.
- It exports `readEvents(body: ReadableStream<Uint8Array>): AsyncIterable<HarnessEvent>`
  which yields one `HarnessEvent` per SSE block, in wire order.
- **Chunk boundaries are irrelevant to the result.** The same byte sequence delivered as one
  chunk, as one-byte chunks, or split at an arbitrary point mid-JSON, mid-`data:` line, or
  between `\n` and `\n` must yield an identical event list. Test this explicitly with at
  least a one-byte-at-a-time case.
- The parser yields the event parsed from the `data:` JSON. `seq` and `kind` are taken from
  the JSON body, which is authoritative. The `id:` and `event:` lines are part of the wire
  format and must be parsed without error but the JSON body is what is returned.
- Unknown fields inside `data:` JSON are preserved or ignored without throwing. An event
  whose `kind` is not one of the six documented kinds must be **skipped**, not thrown on,
  and must not stop the stream (forward compatibility: a future v1 event kind must not
  break an existing client).
- A `\r\n` line ending is handled identically to `\n`.
- SSE comment lines (a line beginning with `:`) are ignored.
- A trailing block without its final blank line — i.e. the stream ends right after a
  complete `data:` line — is still yielded before the iterable finishes.
- Iteration finishes cleanly when the stream ends. The reader releases its lock on the
  stream when iteration completes or is broken out of early.
- Blank/whitespace-only input yields zero events.
