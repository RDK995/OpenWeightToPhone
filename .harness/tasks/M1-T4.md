Tier: Mid — reason: **not low risk.** This is an unauthenticated static file server. The
project's own constraints state "Static PWA assets are served unauthenticated ... Tailnet
membership is the security boundary for the app shell." A containment bug therefore
discloses arbitrary files from the operator's Mac to every device on the tailnet, and the
failure is silent. Containment is milestone acceptance criterion 2 in its own right.

Goal:
Implement architecture component **C4 — PWA Asset Server** at `src/host/pwa-server.ts`:
serve the built PWA bundle over loopback for Tailscale Serve to publish at `/app`, serving
only files that resolve inside the configured bundle root.

Acceptance Criteria:
Create `src/host/pwa-server.ts` exporting:

A. `export function resolveAssetPath(bundleRoot: string, requestPath: string): string | null`
   A **pure, synchronous, separately testable** containment function. This is the security
   boundary; keep it free of I/O other than the filesystem checks named below.
   It returns an absolute path that is provably inside `bundleRoot`, or `null` to mean
   "refuse". It must return `null` — never a path — for every one of these:
   - `requestPath` containing a NUL byte (`\0`) before or after decoding.
   - `requestPath` that fails to `decodeURIComponent` (malformed percent-escape).
   - any path whose resolved location is not `bundleRoot` itself or a descendant of
     `bundleRoot`. Compare with `path.resolve` and require the resolved path to equal
     `bundleRoot` or to start with `bundleRoot + path.sep`. A prefix-string comparison
     alone is NOT sufficient — `"/root/x-evil"` must not pass for root `"/root/x"`.
   - any path that, after `fs.realpathSync` of the resolved target (when it exists),
     escapes `bundleRoot` — i.e. a symlink inside the bundle pointing outside it must be
     refused. `realpathSync` the bundle root too, so the comparison is between two real
     paths. If the target does not exist, `realpathSync` will throw: that is a plain
     miss, so return the resolved path only if the containment check on the resolved
     (non-real) path passed, and let the caller 404 on the missing file.
   Required normalisation, in this order:
   1. Strip a query string or fragment if present (`?`, `#`).
   2. `decodeURIComponent` the path. Then check for NUL and re-check containment on the
      decoded value — decoding is what turns `%2e%2e%2f` into `../`, so containment must
      be evaluated AFTER decoding, never before.
   3. If the decoded path is `/app`, `/app/`, or starts with `/app/`, strip that `/app`
      prefix. Import `APP_MOUNT_PATH` from `./config.ts` rather than writing `/app`
      literally. **Why both forms must work:** it is not established whether Tailscale
      Serve's `--set-path /app` strips the prefix before proxying to this server, so the
      server must serve the same content for `/app/index.html` and for `/index.html`.
      Handle the prefix only as a whole path segment — `/appliance/x` must NOT be treated
      as prefixed.
   4. A path ending in `/` (or empty after stripping) maps to `index.html` in that
      directory.
   5. If the resolved target is an existing directory, map to `index.html` inside it.

B. `export function contentTypeFor(filePath: string): string`
   Extension → type, at minimum: `.html` → `text/html; charset=utf-8`,
   `.js`/`.mjs` → `text/javascript; charset=utf-8`, `.css` → `text/css; charset=utf-8`,
   `.json` → `application/json; charset=utf-8`,
   `.webmanifest` → `application/manifest+json`, `.svg` → `image/svg+xml`,
   `.png` → `image/png`, `.ico` → `image/x-icon`, `.txt` → `text/plain; charset=utf-8`.
   Anything else → `application/octet-stream`. Extension matching is case-insensitive.

C. `export async function handleRequest(request: Request, bundleRoot: string): Promise<Response>`
   - Method not `GET` and not `HEAD` → `405` with an `Allow: GET, HEAD` header.
   - `resolveAssetPath` returns `null`, or the file does not exist, or it is not a regular
     file → `404` with a short plain-text body. **The body must never contain file
     contents, the resolved filesystem path, or the bundle root.** A refusal and a plain
     miss must be indistinguishable to the client: identical status and identical body.
   - Otherwise `200` with the `Content-Type` from `contentTypeFor` and these headers:
     `Cache-Control: no-cache`, `X-Content-Type-Options: nosniff`.
     For `HEAD`, return the same status and headers with an empty body.

D. `export function createPwaServer(options?: { port?: number; bundleRoot?: string }): Bun.Server`
   Uses `Bun.serve`, binding **`hostname: "127.0.0.1"`** — loopback only, never `0.0.0.0`.
   Defaults come from `resolvePwaPort()` and `resolveBundleRoot()` in `./config.ts`.
   Delegates to `handleRequest`.

E. When the module is the entry point (`import.meta.main`), start the server and log the
   bound URL and the bundle root to stdout. Importing the module must NOT start a server.

Also create `test/host/pwa-server.test.ts` using `bun:test`. Build a temporary bundle root
with `mkdtempSync(join(tmpdir(), "bundle-"))` containing `index.html`, `main.js`,
`sub/index.html`, and — outside it, in a sibling temp directory — a `secret.txt` whose
contents are a known sentinel string. Clean up with `rmSync(dir, {recursive:true,force:true})`.
Cover at least:
- `/` and `/index.html` and `/app/` and `/app/index.html` all return `200` with
  `content-type` starting `text/html`, and the same body.
- `/main.js` returns `200` with a `text/javascript` content type.
- `/sub/` returns the nested `index.html`.
- Every one of these returns `404` **and a body not containing the sentinel**:
  `/../secret.txt`, `/../../secret.txt`, `/%2e%2e/secret.txt`, `/..%2fsecret.txt`,
  `/%2e%2e%2fsecret.txt`, `/app/../../secret.txt`, `/subdir/../../secret.txt`,
  `/%00`, `/index.html%00.png`, `/%zz` (malformed escape).
- A symlink created inside the bundle root pointing at the sentinel file outside it
  returns `404` and does not leak the sentinel. (`symlinkSync`.)
- `/appliance/x` is treated as a normal miss, not as the `/app` prefix.
- A `POST` returns `405`.
- The `404` body for a refusal is byte-identical to the `404` body for a plain miss of a
  file that simply is not there.
- `resolveAssetPath("/root/x", ...)` does not accept a sibling directory `/root/x-evil`.
