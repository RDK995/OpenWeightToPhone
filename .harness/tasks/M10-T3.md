Goal:
Add the PWA service worker — a versioned cache and a network-first shell strategy — as a
typed source module that the build emits as a classic (non-module) worker script, and
register it from the browser bootstrap.

Relevant Requirements:
FR2 (Installation). Component C12 (PWA Shell). Architecture risk this exists to answer:
"Service-worker staleness could pin an old build. Mitigated by a network-first strategy
for the shell and a versioned cache name."

Acceptance Criteria:
- New file `web/src/sw.ts`. It must be importable from a Bun test in a NON-browser process
  without throwing: every statement that touches `self`, `caches`, `clients` or
  `addEventListener` must sit behind a guard, in the same spirit as the
  `typeof document !== "undefined"` guard at the bottom of `web/src/main.ts`. Read that
  file's header comment and follow the same discipline.
- It exports:
    export const CACHE_VERSION: string        // e.g. "v1"
    export const CACHE_NAME: string           // `phone-reasoning-shell-${CACHE_VERSION}` — the
                                              // version string MUST appear inside CACHE_NAME
    export const SHELL_SCOPE: string          // "/app/"
    export function shouldHandle(request: { method: string; url: string }, scopeOrigin: string): boolean
    export async function handleShellRequest(
      request: Request,
      deps: {
        fetch: (request: Request) => Promise<Response>;
        cacheMatch: (request: Request) => Promise<Response | undefined>;
        cachePut: (request: Request, response: Response) => Promise<void>;
      }
    ): Promise<Response>
    export function staleCacheNames(existing: readonly string[]): string[]
- `shouldHandle` returns true ONLY for GET requests, on the same origin as `scopeOrigin`,
  whose pathname starts with `SHELL_SCOPE`. It must return false for every other method,
  for cross-origin URLs, and for same-origin paths outside `/app/`. This matters: the
  harness API lives at `/v1/...` on the SAME origin, and its bearer-token, streaming SSE
  requests must never be intercepted or cached by the worker. Add tests proving
  `shouldHandle` is false for `POST /app/x`, for `GET /v1/sessions`, and for a
  cross-origin `GET`.
- `handleShellRequest` implements network-first:
    1. Await `deps.fetch(request)`.
    2. If it resolves with a response whose `ok` is true, store a CLONE of it via
       `deps.cachePut(request, clone)` and return the original response. A rebuilt bundle
       must therefore be returned in preference to anything already cached — this is the
       whole point of the criterion.
    3. If it resolves with `ok === false`, do NOT cache it; fall through to the cache
       (step 4) and, if the cache misses, return the non-ok network response.
    4. If `deps.fetch` REJECTS (offline), await `deps.cacheMatch(request)`; return the hit
       if there is one, and re-throw the original fetch rejection if there is not.
- `staleCacheNames(existing)` returns every name in `existing` that is not `CACHE_NAME`, so
  activation can evict caches from previous versions.
- Behind its environment guard, the worker wires the standard lifecycle: `install` →
  `skipWaiting()`; `activate` → delete `staleCacheNames(await caches.keys())` then
  `clients.claim()`; `fetch` → if `shouldHandle(event.request, self.location.origin)` then
  `event.respondWith(handleShellRequest(event.request, deps))` built over
  `caches.open(CACHE_NAME)`, and otherwise do not call `respondWith` at all (let the
  request go to the network untouched).
- `scripts/build.ts` emits the worker to `web/dist/sw.js` as a CLASSIC script:
  a SECOND `Bun.build` call with `entrypoints: [resolve(root, "web", "src", "sw.ts")]`,
  `target: "browser"`, `format: "iife"`, `naming: "[name].js"`, same `outdir`, and the same
  `if (!result.success) throw` handling as the existing call. Add `"sw.js"` to the returned
  `files` set. It must be `iife`, not `esm`: registering a module service worker
  (`{ type: "module" }`) is not reliably supported on iOS Safari, and the registration below
  deliberately registers a classic worker.
- `web/src/main.ts` registers it, inside the existing `typeof document !== "undefined"`
  guard, guarded further by `"serviceWorker" in navigator`, as
  `navigator.serviceWorker.register("./sw.js")` (relative, so the scope is `/app/`), with the
  returned promise's rejection caught and swallowed (a failed registration must never break
  the app). Do not change anything else in `main.ts`, and do not break
  `test/web/ui/bundle-mount.test.ts`, which imports `main.ts` in a non-browser process.
- New test file `test/web/sw.test.ts` (Bun test, matching neighbouring tests under
  `test/web/`) covering, at minimum:
    * `CACHE_NAME` contains `CACHE_VERSION` (the versioned-cache criterion);
    * the `shouldHandle` cases listed above;
    * **the rebuild case**: seed a fake cache with a response whose body is `"OLD BUILD"`,
      have `deps.fetch` resolve a 200 whose body is `"NEW BUILD"`, and assert
      `handleShellRequest` returns `"NEW BUILD"` AND that `cachePut` was called with a
      response body of `"NEW BUILD"` (so the cache is refreshed, not just bypassed);
    * offline fallback: `deps.fetch` rejects, cache holds `"OLD BUILD"` → returns
      `"OLD BUILD"`;
    * offline with an empty cache: `deps.fetch` rejects, `cacheMatch` resolves `undefined`
      → `handleShellRequest` rejects with the same error;
    * a non-ok (e.g. 500) network response with an empty cache is returned as-is and is NOT
      passed to `cachePut`;
    * `staleCacheNames(["phone-reasoning-shell-v0", CACHE_NAME, "other"])` excludes
      `CACHE_NAME` and includes the other two;
    * importing `web/src/sw.ts` in the test process does not throw (the guard).
- After the build, `web/dist/sw.js` must exist and must NOT contain the substring `export `
  at the top level (i.e. it is not an ES module). Assert that in
  `test/build.test.ts`-style fashion only if it fits the existing file's shape; otherwise
  put it in `test/web/sw.test.ts` by running the build first is NOT required — a simple
  existence+content assertion on `web/dist/sw.js` is acceptable, but if you add it, make
  sure `bun test` still passes from a clean checkout by building first inside the test or by
  skipping when `web/dist/sw.js` is absent. Prefer: add the assertion to
  `test/build.test.ts` where a build is already performed, if that file builds into a
  temporary root — read it before deciding.
