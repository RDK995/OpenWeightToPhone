# Task M11-T9 — Prove the *shipped bundle* carries the fragment-capture wiring

Tier: **Cheap**. Reason for going above Cheap: **none named**. Clearly specified below,
bounded to three named files, verified by a total oracle (`bun test` exit status and
`bun run proof:m11` exit status), and cheap to be wrong about.

## Context — read this, it is the whole point of the task

M11's AC2 was **falsified by a human on a physical iPhone** even though the suite was
**711 pass / 0 fail**. The reason is a proof-design defect, not only a wiring omission:

> Every existing proof of AC2 injected its own `LocationPort` and `StoragePort` and called
> `adoptCredentialFromFragment` directly. All of them proved the function in isolation. None
> asserted that the browser entry point invokes it, and **none asserted against the built
> bundle**. `web/dist/main.js` contained zero occurrences of `adoptCredentialFromFragment` and
> zero of `location.hash` — the bundler had tree-shaken the function out because nothing
> called it. The shipped app had no fragment-capture code in it at all.

Task M11-T8 (already accepted) fixed the wiring: `bootstrap()` in `web/src/main.ts` now calls
`adoptCredentialFromFragment` before it constructs the API client, `web/src/location-port.ts`
provides `createWindowLocation(win)`, and `test/web/main-bootstrap.test.ts` fails if the call
is removed.

**What is still missing is a proof against the artefact that is actually served.**
`test/web/main-bootstrap.test.ts` imports `web/src/main.ts` (TypeScript source). It would stay
green even if the bundler dropped the code on the way to `web/dist/main.js` — which is
precisely the failure that shipped. Your job is to close that hole.

Read `web/src/main.ts` first: `bootstrap(root, deps?)` takes optional `storage`, `location`,
`createTarget` and `createApiClient`, each defaulting to the real collaborator. The bundle
exports `bootstrap`, `mount`, `createWindowLocation`, `adoptCredentialFromFragment` and
`createCredentialStore`. Read `test/web/main-bootstrap.test.ts` for the fake shapes and
`test/web/ui/bundle-mount.test.ts` for the cache-busting built-bundle import pattern
(`importBuiltBundle`) — reuse both rather than inventing new ones.

## Goal

1. Add a test that builds the bundle and proves **the built `web/dist/main.js` pairs a phone
   from a `#t=<token>` fragment** — behaviourally, by running the built code, not only by
   grepping it.
2. Rewrite `src/host/m11-proof.ts`'s Phase 2 so AC2's agent-provable half no longer rests on
   calling the adopter with a fake location. It must exercise the **built bundle's**
   `bootstrap()` and chain the token it recovers into the live authenticated call.
3. One-word type fix in `web/src/main.ts` (see below).

## Required: `test/web/bundle-fragment.test.ts` (new)

A `beforeAll` that `await build()` (import `build` from `../../scripts/build.ts`, as
`test/web/ui/bundle-mount.test.ts` does). Then:

### 1. The process really is non-browser
Assert `typeof document === "undefined"` and `typeof window === "undefined"`, so the assertions
below cannot be passing by accident against a DOM.

### 2. Static assertion — the tree-shaking guard
Read `web/dist/main.js` as text and assert it contains `"adoptCredentialFromFragment"`,
`"URLSearchParams"` and `"replaceState"`. Include a comment stating this is valid **because
`scripts/build.ts` sets `minify: false`**, and that if minification is ever enabled this
assertion will fail loudly and should be replaced by the behavioural test below rather than
deleted. Also assert the bundle is non-empty and contains no `"interface "` (matching the
existing convention in `test/build.test.ts`).

This assertion is the direct regression guard for the exact defect that shipped: it fails
against the pre-fix bundle, which contained zero occurrences of the identifier.

### 3. Behavioural assertion — the strong one
Dynamically import the built `web/dist/main.js` with the cache-busting query used by
`test/web/ui/bundle-mount.test.ts`'s `importBuiltBundle` (a stale module-cache hit would let
this test pass against a bundle from a previous run — that risk is real here, so do not skip
the cache-buster). Then call the **bundle's** `bootstrap`:

```ts
mod.bootstrap(fakeRoot, { storage, location, createTarget, createApiClient })
```

with `createMemoryStorage()`, a fake `LocationPort` whose hash is `"#t=bundle-token-xyz"` and
origin `"https://bundle.example.test"`, a `createTarget` returning a paint-recording
`RenderTarget`, and a `createApiClient` stub that records the `baseUrl` it was constructed
with. Assert:

- the storage now holds a credential with `token === "bundle-token-xyz"` and
  `baseUrl === "https://bundle.example.test"`;
- the fake location's `clearHash()` was called and its `hash` reads `""` afterwards;
- the recorded `baseUrl` is `"https://bundle.example.test"` and **not** `""` (the ordering
  proof, carried through the bundle);
- `mod.bootstrap` is a function and `typeof mod.createWindowLocation === "function"` (so
  tree-shaking cannot silently drop the real `LocationPort` adapter either).

Add a comment on the first of these saying: *this assertion fails if the adoption call is
removed from `bootstrap()`, and it fails if the bundler drops the code on the way to
`web/dist/main.js` — the failure mode that shipped and was caught only on a physical device.*

### 4. Negative control
Run `bootstrap` again with a **fresh** memory storage and a location with **no fragment**
(`hash: ""`). Assert no credential is written, `clearHash()` is not called, and the recorded
`baseUrl` is `""`. This proves assertion 3 is discriminating rather than always-true.

Do not weaken, skip or `try/catch`-swallow any assertion. No `it.skip`, `describe.skip` or
`.todo`. A test that catches its own failure and returns is treated as a FAIL for this task.

**Ordering hazard you must handle:** `test/build.test.ts` deletes `web/dist` in its `afterEach`.
Your test must therefore build in its own `beforeAll` and must not assume `web/dist` already
exists. Do not add cleanup that deletes `web/dist` — leave the bundle in place when the file
finishes.

## Required: `src/host/m11-proof.ts` — Phase 2 rewrite

Phase 2 is currently headed `PHASE 2: AC2 AGENT-PROVABLE HALF - CREDENTIAL STORE AND LIVE AUTH`
and calls `adoptCredentialFromFragment(store, fakeLocation)` directly. Replace that direct call
with a chain through the built bundle. Keep the phase's existing live-auth half.

New Phase 2 sequence:

1. `await build()` (import from `../../scripts/build.ts`), so the proof runs against a freshly
   built bundle rather than whatever happens to be on disk. Print the outdir.
2. Read `web/dist/main.js` and print the **count** of occurrences of
   `adoptCredentialFromFragment` in it. Fail the phase if it is `0`. Print
   `"Built bundle contains fragment-capture code: confirmed"` when non-zero.
3. Take the **real** pairing URL from `pairingUrlWithToken(readToken())` as it does today,
   extract its fragment, and build a fake `LocationPort` from it (hash = the real fragment,
   origin = `resolveBaseUrl()`).
4. Dynamically import the built `web/dist/main.js` (cache-busted) and call its `bootstrap`
   with that location, a `createMemoryStorage()`, a paint-recording `createTarget` and a
   `createApiClient` stub that records `baseUrl` and exposes the `getToken` it was given.
5. Assert and print, each as its own `confirmed`/`FAIL` line:
   - the bundle's `bootstrap` ran without throwing;
   - the hash was cleared and the fake location's hash is now empty;
   - a credential is present in the memory storage;
   - the recorded API-client `baseUrl` equals `resolveBaseUrl()` (the ordering proof);
   - the api client's `getToken()` returns a non-empty token.
6. **Chain to the live call.** Read the token back **only** out of the memory storage the
   bundle wrote (never from `readToken()` again at this point — say so in a comment), and use
   it as the bearer for `GET ${baseUrl}/v1/profiles`. Assert **200**. Keep the existing
   unauthenticated `GET /v1/profiles` → **401** control.

Update the phase heading to make clear what is now proven, e.g.
`=== PHASE 2: AC2 AGENT-PROVABLE HALF - BUILT BUNDLE ADOPTS THE FRAGMENT, THEN LIVE AUTH ===`,
and keep the existing `NOTE: AC2's optical camera step is HUMAN-ATTESTED and NOT proven here.`
line. Update the numbered `M11 ACCEPTANCE CRITERIA SUMMARY` line 2 so it describes what is
actually proven now (the **built bundle** adopting the fragment, then a live 200), and keep its
"optical scan is human-attested, not proven here" caveat.

Update the file's header comment to record that Phase 2 exercises the built bundle's
`bootstrap()` — and **why**: proving the adopter in isolation is what let the shipped bundle
lose the code entirely.
