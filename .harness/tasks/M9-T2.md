```ts
import type { Conversation, Turn } from "../conversation-store";
import type { Telemetry } from "../sse-reader";
import type { Profile } from "../api-client";

export interface TelemetryDisplay {
  tokensPerSecond: number;
  evalCount: number;
  quantization: string;
  contextLimit: number;
}

export type GenerationDisplay =
  | { kind: "idle" }
  | { kind: "queued"; position: number }
  | { kind: "model-loading" }
  | { kind: "streaming" }
  | { kind: "complete"; telemetry: TelemetryDisplay }
  | { kind: "cancelled" }
  | { kind: "error"; code: string; message: string };

export interface ConversationListItem {
  id: string;
  title: string;
  updatedAt: string;
  selected: boolean;
}

export interface TranscriptEntry {
  role: "user" | "assistant";
  content: string;
  cancelled: boolean;
  createdAt: string | null;
  pending: boolean;
}

export interface UiState {
  conversations: readonly Conversation[];
  selectedConversationId: string | null;
  profiles: readonly Profile[];
  generation: GenerationDisplay;
  streamingText: string;
}

export interface ViewModel {
  conversations: readonly ConversationListItem[];
  transcript: readonly TranscriptEntry[];
  profiles: readonly Profile[];
  selectedProfileId: string | null;
  generation: GenerationDisplay;
}

export function buildViewModel(state: UiState): ViewModel;
```

2. **Purity.** `buildViewModel` must not mutate `state` or anything reachable from it,
   must not read any global (no `Date`, no `Math.random`, no `document`, no
   `localStorage`), and must be deterministic: calling it twice on the same input yields
   deeply equal results. Prove all three in tests, including a test that deep-freezes the
   input state (`Object.freeze` on the state, its `conversations` array and each
   conversation, recursively over arrays/objects) and asserts no throw.

3. **Conversation list, newest first.** `conversations` is every conversation in
   `state.conversations`, mapped to `ConversationListItem`, sorted by `updatedAt`
   descending (compare the ISO-8601 strings; they are ISO so lexicographic ordering is
   chronological — but write the comparison so it is obviously a date-descending sort).
   Ties on `updatedAt` break by `id` ascending, so the order is total and stable.
   `selected` is true for exactly the item whose `id === state.selectedConversationId`,
   and false for all others (all false when nothing is selected).
   Test with at least: empty list; several conversations deliberately supplied in the
   WRONG order proving the sort actually happens; a tie on `updatedAt`; a selected id that
   matches nothing.

4. **Transcript, in order.** When `state.selectedConversationId` names a conversation
   present in `state.conversations`, `transcript` is that conversation's `turns` in their
   stored array order — NOT re-sorted, NOT reversed — each mapped to a `TranscriptEntry`
   with `pending: false` and `createdAt` copied through. When nothing is selected, or the
   selected id matches no conversation, `transcript` is `[]`.
   Test that stored order is preserved even when `createdAt` values are out of order —
   this proves you preserved order rather than sorted by date.

5. **The pending (in-flight) entry — display only.** Exactly one trailing
   `TranscriptEntry` with `pending: true`, `role: "assistant"`, `cancelled: false`,
   `createdAt: null` is appended to `transcript` when there is text in flight, and the
   text is chosen as: `state.streamingText` if it is non-empty; otherwise the selected
   conversation's `pending.partialText` if that exists and is non-empty; otherwise NO
   pending entry is appended at all. There is never more than one pending entry, and none
   when nothing is selected.
   IMPORTANT — do not confuse this with persistence. FR4 states the client MUST NOT append
   turns around a generation; the service appends both turns itself. This pending entry is
   a display projection only: it is derived from `streamingText`/`pending.partialText` and
   is never written back to the store. Say so in a short comment above it.

6. **Generation display states are distinct.** `generation` is passed through from
   `state.generation` unchanged. Tests must prove all seven kinds project distinctly and
   that a consumer can tell them apart:
   - `queued` carries `position` as a **1-based** number, passed through unmodified from
     the harness `queued` event's `position` (1 means next to run). Test position 1 and a
     larger position. Do NOT add 1, subtract 1, or clamp it.
   - `model-loading` is its own kind, distinct from both `queued` and `streaming`.
   - `complete` carries a `TelemetryDisplay`.

7. **Telemetry projection.** Export and test a mapping from the wire `Telemetry` (see
   `web/src/sse-reader.ts`, snake_case) to `TelemetryDisplay` (camelCase), covering
   exactly the four fields FR4 names:
   `tokens_per_second` -> `tokensPerSecond`, `eval_count` -> `evalCount`,
   `quantization` -> `quantization`, `context_limit` -> `contextLimit`.
   Export it as `export function toTelemetryDisplay(telemetry: Telemetry): TelemetryDisplay`.
   It must ignore the wire type's other fields and its index signature rather than leaking
   them into the display type. Test that an unrelated extra wire field does not appear on
   the result.

8. **`profiles` and `selectedProfileId`.** `profiles` passes through
   `state.profiles` unchanged. `selectedProfileId` is the selected conversation's
   `profileId`, or `null` when nothing is selected or the selected id matches nothing.
   Never hardcode a profile id anywhere — `test/no-hardcoded-profile-ids.test.ts` scans for
   that and must keep passing. Read it before you write any test fixture.
