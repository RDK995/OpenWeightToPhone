## M9 — The chat view and conversation list drive the client in the browser

Status: DONE

### Outcome

The browser UI: a conversation list and a chat view that translate user actions into
coordinator calls and render streamed deltas, queue position, the model-loading state and
completion telemetry.

**What this agent can and cannot prove.** There is no browser under the agent's control —
no Node, no Playwright, and the only iOS device is the human's. The mechanical proof is
therefore confined to the layer that does not need a DOM: the view-model is a pure function
from store and coordinator state to what should be displayed, unit-tested headlessly, and
the bundle is proven to build and to load without throwing when mounted against injected
state. What the browser renders is attested on the device in M10. The design consequence is
deliberate: keep the DOM glue thin enough that the attested part is small.

### Architecture

C10, C12

Realised: C10 (UI) was created at `web/src/ui/` as four modules with a deliberate seam:
`view-model.ts` (pure state -> display projection), `actions.ts` (the one-to-one map onto
C9), `mount.ts` (holds state, repaints) — all DOM-free and headlessly tested — and
`dom-target.ts`, the single DOM-touching module, kept small because its rendering is
attested on the device in M10, not here. `render-target.ts` declares the `RenderTarget`
seam between the two halves. C12 (PWA Shell) advanced only as far as M9 needs: `web/public/`
is unchanged and `web/src/main.ts` became the real bundle entry point that C4 serves. The
manifest, icons and service worker remain M10's.

TWO DEVIATIONS ARE RECORDED, both `Material: no`, under the `**M9 — ...**` entry in
`## Deviations` of `.harness/architecture.md`: (1) C9 gained `listProfiles()` and
`setProfile()`, which the written `C10 -> C9` interface does not name — forced by the agreed
dependency graph, since C10 does not depend on C7 and so cannot fetch profiles itself, while
AC3 forbids bypassing the coordinator; both are one-to-one pass-throughs onto collaborators
C9 already holds. (2) C10's internal four-module division, recorded so a reader is not
surprised by a DOM-free UI component. Neither moves a boundary, changes a technology, nor
changes which component owns a responsibility.

Evidence per acceptance criterion:

**AC1 — view-model is a pure function; list newest first; transcript in order.**
`web/src/ui/view-model.ts` exports `buildViewModel(state: UiState): ViewModel`. Purity is
tested three ways: a no-mutation test, a determinism test (called twice, deeply equal), and a
test that recursively deep-freezes the state, its `conversations` array and each conversation
and asserts no throw. The verifier read the freeze helper and confirmed it recurses via
`Object.getOwnPropertyNames` rather than freezing only the top level. The list sorts by
`updatedAt` descending with ties broken by `id` ascending, proved by a fixture supplied in
deliberately WRONG order (ids [1,2,3] with updatedAt [28,30,29], expecting [2,3,1]) and a
same-`updatedAt` tie fixture (ids [c,a,b] expecting [a,b,c]) — the verifier checked the
fixtures are not already sorted, so the tests would fail if the sort were removed. Transcript
order is proved by a fixture whose `createdAt` values are deliberately out of order
([10:05, 10:00, 10:10]) asserting stored array order is preserved — that is what distinguishes
"in order" from "date-sorted". No DOM: the module touches no global.

**AC2 — queue position 1-based, model-loading, and completion telemetry as distinct states.**
All seven `GenerationDisplay` kinds (idle, queued, model-loading, streaming, complete,
cancelled, error) are tested as distinct discriminated variants. `queued.position` is asserted
passed through unmodified at position 1 AND at position 5, with no off-by-one adjustment or
clamping. `model-loading` is asserted distinct from both `queued` and `streaming`.
`toTelemetryDisplay` maps exactly the four values FR4 names — `tokens_per_second` ->
`tokensPerSecond`, `eval_count` -> `evalCount`, `quantization`, `context_limit` ->
`contextLimit` — and a test asserts an unrelated extra wire field does NOT leak onto the
result via `Object.keys`.

**AC3 — send, cancel, choose profile map one-to-one onto coordinator calls, no bypass.**
`web/src/ui/actions.ts` is a 52-line pure delegation layer. Each of the six actions makes
exactly one call on the injected coordinator: `send`->`coordinator.send`,
`cancel`->`coordinator.cancel`, `chooseProfile`->`coordinator.setProfile`,
`resumeIfInterrupted`->`coordinator.resumeIfInterrupted`, `listProfiles`->`coordinator.listProfiles`,
`createConversation`->`coordinator.createConversation`. Recording-fake tests assert exact call
count, exact forwarded arguments, error propagation, and — the assertion that makes
"one-to-one" real rather than a restatement — that the other five coordinator methods received
ZERO calls, so mis-wiring one action to another method fails.
"No bypass" is enforced structurally and **proved empirically**: the verifier backed up
`actions.ts` outside the repo, injected a real bypass
(`import { HarnessApiError } from "../api-client";`), and the suite FAILED with
`Found bypass import from "../api-client" in actions.ts` (25 pass / 1 fail); the file was then
restored and confirmed byte-identical by `diff`, with the suite green again. The test permits
`import type` lines (which carry no runtime capability) via a negative lookahead, so it is not
passing merely by matching nothing. The same structural technique is applied to `mount.ts`
and was empirically proved there too: injecting `const _x = typeof document;` made
`mount.test.ts` FAIL with `Found document in mount.ts`, then restored byte-identical.

**AC4 — `Bun.build` produces the bundle the asset server serves, and it mounts against
injected state without throwing.**
`bun run build` exits 0 and writes `web/dist/index.html` and `web/dist/main.js` (42,047 bytes
— the real client, not the former 6-line shell). That `web/dist` is genuinely what M1's asset
server serves was confirmed independently by the verifier reading the resolution chain itself
rather than accepting it: `src/host/pwa-server.ts` defaults `bundleRoot` to
`resolveBundleRoot()`, and `src/host/config.ts` resolves that to `<repoRoot>/web/dist`, the
same path `scripts/build.ts` writes to.
`test/web/ui/bundle-mount.test.ts` asserts `typeof document === "undefined"` in-process (so the
browser guard is demonstrably exercised, not assumed), dynamically imports the BUILT
`web/dist/main.js` — not the TypeScript source — over a `file://` URL with a cache-busting
query so a stale bundle can never be mistaken for a fresh one, asserts the import does not
throw, asserts `typeof mod.mount === "function"`, then calls
`mod.mount({ target, coordinator, store })` with injected fixtures and asserts it does not
throw AND that the painted object is a real view model whose `conversations` reflect the
injected fixtures newest-first (`["fixture-conv-newer","fixture-conv-older"]`) — not merely
that nothing threw.
**This proof was itself proved non-vacuous.** The verifier backed up `web/src/main.ts`,
appended `document.title = "boom";` OUTSIDE the `typeof document !== "undefined"` guard, and
the test FAILED exactly as it should:
`ReferenceError: document is not defined at .../web/dist/main.js:1345:1` (3 pass / 2 fail).
The file was restored and confirmed byte-identical, and the suite returned to green. That
failure is the strongest single piece of evidence in this milestone: it shows the test runs
against the real built artefact and would catch a bundle that could not load.

**Proof boundary, restated honestly.** No browser was run. Nothing here attests what the
device actually renders — `web/src/ui/dom-target.ts` (88 lines) is the only module whose
behaviour is unproven by this milestone, and that is deliberate: it is why the DOM-free/DOM

### Follow-ups

- **`MountHandle.getState()` returns only a SHALLOW copy.** Mutating a top-level field of the
  returned state does not affect the mount (tested), but mutating a nested object — e.g.
  `getState().conversations[0]` — would still reach the mount's internal list. The verifier
  flagged this explicitly. Not exercised by any M9 criterion and no caller does it today;
  worth either deep-copying or freezing the returned state when a real caller appears.
- **`web/src/ui/dom-target.ts` re-renders whole lists via `replaceChildren` on every paint**
  rather than diffing. Simplest correct implementation and deliberately so, but if M10's
  on-device check surfaces sluggishness on a long transcript, this is the first place to look.
- **`web/src/ui/actions.ts` per-action tests assert return values with `toEqual` rather than
  `toBe`** in some cases. The packet asked for identity assertions; `toEqual` would still pass
  if an action reconstructed an equal object instead of passing the coordinator's value
  through. The implementation was read and confirmed to be a direct `return coordinator.X(...)`,
  so this is a test-strength gap rather than a defect. Worth tightening.
- **`bootstrap()` in `web/src/main.ts` is not mechanically tested.** It is inside the browser
  guard by construction, so no headless test reaches it; only its non-throwing import is
  proved. Its behaviour with and without a stored credential is part of what M10 and M11
  attest on the device.
- **The written `C10 -> C9` interface in `.harness/architecture.md` still lists only
  `send`/`cancel`/`resumeIfInterrupted` + a subscription**, while C9 now also exposes
  `createConversation`, `listProfiles` and `setProfile`. Four separate `Material: no`
  deviations (M3, M5, M8, M9) now qualify that one line. Consider rewriting the interface line
  itself to match what exists, and collapsing the deviations into it.
- **There is no subscription in the `C10 -> C9` interface as built.** The architecture names
  "a subscription for streamed deltas and status changes"; M9 instead threads the existing
  `GenerationHandlers` callbacks through `actions.send`, and `mount` exposes
  `setGeneration`/`setStreamingText` for a caller to drive. That is sufficient for M9's
  criteria and nothing here needs it, but wiring the handlers to the mount is still to be done
  by whichever milestone first needs live streaming on screen.
