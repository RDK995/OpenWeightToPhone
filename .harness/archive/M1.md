## M1 — The app shell is served on the same origin as the harness API

Status: DONE

### Outcome

A page fetched from `https://ryans-mac-studio.tailc3648a.ts.net/app/` is served by this
repository's asset server, while `https://ryans-mac-studio.tailc3648a.ts.net/v1/...`
continues to reach the untouched harness on the same scheme, host and port. This is the
constraint the entire design rests on — the harness sends no CORS headers, so if the app
cannot be published on the harness's own origin, nothing else in this plan can work. It is
therefore proven first, before any client code exists.

Recon established that the mapping is currently **absent**: `tailscale serve status` shows
only `/ proxy http://127.0.0.1:7787`, and `GET https://<host>/app/` returns `401` because
the `/` handler proxies it to the harness. Adding the second handler is operator
configuration outside this repository and may require the operator to run the install
script themselves; the script must therefore be idempotent and must say clearly when the
mapping is missing rather than failing obscurely.

This milestone also establishes the repository scaffolding, the Bun toolchain and the
baseline commit convention. Those are tasks, not criteria.

**Provenance of the served bytes — how "from this repository's built bundle" was proven.**
Byte-identity alone shows only that two files match; it does not show the wire bytes were
*produced by* this repository. So provenance was established causally, by mutating the
build input and watching the public URL follow:

| Step | Command | Result |
| --- | --- | --- |
| A — negative control | `curl .../app/__provenance-probe.txt` | **404** before injection |
| B — inject into **source** | write nonce `M1-PROVENANCE-1787933738-e48db3f408fbf81e` to `web/public/__provenance-probe.txt`; `bun run build` | exit 0, dist now lists the probe file |
| C — fetch via **tailnet origin** | `curl https://ryans-mac-studio.tailc3648a.ts.net/app/__provenance-probe.txt` | **200** `text/plain`, body **exactly the nonce** |
| D — remove from source, rebuild | `rm web/public/__provenance-probe.txt`; `bun run build` | exit 0 |
| E — re-probe | `curl .../app/__provenance-probe.txt` | **404** again |
| F — restoration | sha256 of `web/dist/index.html`, `ls web/public`, `git status` | identical sha, probe file gone, tree clean |

The nonce was generated from `/dev/urandom` seconds earlier, so bytes carrying it at the
public URL cannot have originated anywhere but this repository's build. The 404 → 200 →
404 transition tracking two `bun run build` invocations proves the causal chain
`web/src` + `web/public` → `bun run build` → `web/dist` → pid 9227 → Tailscale Serve
`/app` → the public origin. Method used: **causal marker injection**, corroborated by
byte-identity and by the server's own response-header fingerprint.

**Incidental finding — the `/app` prefix question is now settled.** Probing
`.../app/app/index.html` returns **200** through the tailnet while the identical path sent
straight to `http://127.0.0.1:7788/app/app/index.html` returns **404**. The only
difference is Tailscale, so **Tailscale Serve strips the `/app` prefix before proxying**;
the asset server receives `/…`, not `/app/…`. `stripMountPrefix` is therefore defensive
only and is not exercised on the production path. It is harmless and was left in place —
see Follow-ups.

### Follow-ups

- **No TypeScript type-checking gate.** `tsc` is not installed and there is no npm/npx, so
  nothing type-checks the repository; `bun test` executes TypeScript without checking it.
  `bunx tsc --noEmit` reports errors repo-wide purely because `@types/bun` and `@types/node`
  are absent. Adding those two dev dependencies and a `typecheck` script would give every
  later milestone a real gate. Deliberately not done here: it needs a network install and is
  outside M1's three criteria.
- **`createPwaServer`'s loopback binding and the `import.meta.main` guard are proven by
  source inspection, not by a test.** The T4 verifier flagged both as having no test
  coverage. `hostname: "127.0.0.1"` is a literal so it is a static guarantee, and the live
  `lsof` check above confirms the actual bind — but a regression test would be cheap.
- **The tailnet hostname is a hardcoded default** in `resolveBaseUrl` (overridable via
  `OPENWEIGHT_HARNESS_BASE_URL`). Deriving it from `tailscale status --json` would remove
  the literal. Out of scope for M1.
- **RESOLVED in phase 2: Tailscale Serve strips the `/app` prefix before proxying.**
  Proven by a discriminating probe — `.../app/app/index.html` returns `200` through the
  tailnet but `404` when sent directly to `http://127.0.0.1:7788/app/app/index.html`. The
  asset server therefore receives `/…`, never `/app/…`, and `stripMountPrefix` is dead
  code on the production path. It is harmless and was deliberately **not** removed in this
  phase (out of scope: no criterion depends on it, and the tolerance guards against a
  future Serve configuration that does not strip). A later milestone may drop it, but
  should keep the 23 containment tests intact if it does.
- **`web/dist` is gitignored**, so the served bundle is a build product. M10's launch agent
  will need to guarantee `bun run build` has run before the server starts.
- The asset server was left running in the background on `127.0.0.1:7788` at the end of
  this phase (`bun run src/host/pwa-server.ts`, log at `/tmp/pwa-server.log`). It is not yet
  supervised; the launchd agent is M10.
- **OPTIONAL, from the cycle-1 review: `test/build.test.ts` deletes and recreates the
  repository's real `web/dist`**, which is the same directory the live asset server serves
  from — not a temp directory. Running `bun test` therefore opens a brief window where the
  live server 404s on every request, and a process killed mid-suite could leave `dist`
  deleted. Not a defect against M1's criteria (the reviewer confirmed `web/dist/index.html`
  and the live `/app/` response were byte-identical before and after its own `bun test`
  run), but it becomes a real availability concern once M10 supervises the server
  continuously. Suggested fix: point the test at a temp directory through the
  `options?.root` seam `scripts/build.ts` already accepts — the pattern
  `pwa-server.test.ts` and `serve-install.test.ts` already use.
